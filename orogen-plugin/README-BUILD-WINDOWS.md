# OROGEN — сборка VST3 в Visual Studio 2022 (Windows x64)

В архиве лежит всё, что нужно для сборки плагина под Windows: исходники
DSP-ядра, исходники обёртки, `CMakeLists.txt`, пресеты и готовые скрипты.
JUCE 8.0.15 скачивается автоматически при первой сборке (нужен интернет и git).
Текущая ревизия проверена в Linux; **сборка на Windows/MSVC здесь не выполнялась**.
В архиве исходники, а не готовый Windows-бинарник.

---

## 1. Что должно быть установлено

| компонент | версия | откуда |
|---|---|---|
| **Visual Studio 2022** | 17.x, редакция любая (Community бесплатна) | visualstudio.microsoft.com |
| Рабочая нагрузка | **«Разработка классических приложений на C++»** (Desktop development with C++) | VS Installer |
| **CMake** | ≥ 3.22 | идёт в комплекте с VS 2022; скрипт найдёт его сам |
| **Git** | любая | git-scm.com — нужен CMake, чтобы скачать JUCE |

Отдельно ставить CMake не обязательно: скрипт ищет его сначала в `PATH`, потом
в каталоге VS 2022 (`…\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin`).

Проверка, что всё на месте (PowerShell):

```powershell
git --version
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -property installationPath
```

## 2. Быстрый старт

Распакуйте архив, откройте консоль в папке `OROGEN-vst3-vs2022` и запустите:

```bat
build_vst3.bat
```

Скрипт делает четыре шага: находит CMake → конфигурирует проект генератором
**Visual Studio 17 2022 / x64** → собирает цель `OROGEN_VST3` в конфигурации
`Release` → копирует бандл в `dist\OROGEN.vst3`.

Сборка Debug:

```bat
build_vst3.bat Debug
```

PowerShell-вариант (то же самое, с цветным выводом и понятными ошибками):

```powershell
powershell -ExecutionPolicy Bypass -File .\build_vst3.ps1
```

Установка сразу в системную папку VST3 (нужны права администратора):

```bat
set INSTALL_VST3=1
build_vst3.bat
```

Или вручную скопируйте `dist\OROGEN.vst3` в
`C:\Program Files\Common Files\VST3\`.

## 3. Что где лежит после сборки

```
build-vs2022\                              рабочая папка CMake (можно удалить)
  OROGEN_artefacts\Release\VST3\OROGEN.vst3   собранный бандл
  OROGEN.sln                                 решение для Visual Studio
dist\OROGEN.vst3                           копия бандла (это ставить в DAW)
```

Открыть проект в самой Visual Studio: двойной клик по
`build-vs2022\OROGEN.sln`, затем в Solution Explorer выбрать проект `OROGEN`
и собрать конфигурацию `Release | x64` — получится тот же бандл.

## 4. Требования к машине

* Windows 10/11, x64 (сборка предназначена для x64; текущая ревизия
  не проверялась на Windows, ARM64 тоже не проверялась);
* ~2 ГБ свободного места (JUCE + объектные файлы + бандл);
* сборка первого раза: 10–20 минут (скачивание JUCE + 3 минуты на сам плагин),
  повторная — около минуты.

## 5. Если интернет недоступен или JUCE уже есть

Скрипт не скачивает JUCE, если задана переменная `JUCE_PATH`:

```bat
set JUCE_PATH=C:\JUCE
build_vst3.bat
```

`JUCE_PATH` должен указывать на корень репозитория JUCE (внутри — папка
`modules`). Версия — JUCE 8.0.15 (более старые 8.x тоже должны подойти, 7.x —
нет: проект использует API 8).

Альтернатива — пресет CMake:

```bat
cd orogen-plugin
cmake --preset vs2022-local-juce -DOROGEN_JUCE_PATH=C:/JUCE
cmake --build build-vs2022 --config Release --target OROGEN_VST3
```

## 6. Частые проблемы

| симптом | причина и что делать |
|---|---|
| `CMake not found` | не установлена рабочая нагрузка C++ в VS 2022; запустите VS Installer → «Изменить» → добавить «Разработка классических приложений на C++» |
| `git not found in PATH` | поставьте Git for Windows или задайте `JUCE_PATH` на локальную копию JUCE |
| ошибка при скачивании JUCE (`RPC failed`, таймаут) | сеть/прокси; повторите, либо склонируйте вручную: `git clone --depth 1 --branch 8.0.15 https://github.com/juce-framework/JUCE.git C:\JUCE` и `set JUCE_PATH=C:\JUCE` |
| сборка падает на `juceaide` | почти всегда не хватает прав/места или антивирус блокирует запуск; попробуйте `build_vst3.bat` из обычной консоли без антивирусного «песочного» режима |
| DAW не видит плагин | проверьте, что папка `C:\Program Files\Common Files\VST3\OROGEN.vst3\Contents\x86_64-win\OROGEN.vst3` существует; в DAW включите сканирование VST3 и укажите стандартную папку |
| `LNK1181: cannot open input file '…juce…lib'` | почти всегда несовпадение конфигураций (Debug/Release) — собирайте целиком через скрипт, он всегда задаёт `--config` |
| предупреждения C4244/C4267 | это JUCE-модули на `/W4`; на результат не влияют, проект не собирается с `/WX` |

## 9. Примечание о проверке этой сборки

Текущий исходный код собран и проверен в Linux (GCC 14, JUCE 8.0.15):
198 проверок обёртки (включая native GUI) и 334 DSP-проверки прошли; компилятор выдаёт отдельные
предупреждения. VST3 проверен через JUCE-хост: 38/38. Проверки и бинарник относятся
к Linux: **результат компиляции и работы под Windows неизвестен**.

Ранее для MSVC в код внесены три правки переносимости:

1. `__builtin_popcount` заменён на переносимый `orogen::popCount()` — MSVC такого
   встроенного не имеет;
2. `M_PI` заменён на константу `kPi` (MSVC требует `_USE_MATH_DEFINES`);
3. блоки `#pragma GCC diagnostic` обёрнуты в `#if defined(__GNUC__)` — иначе MSVC
   выдаёт C4068, а флаги `-w`/`-O2` в CMake теперь применяются только к GCC/Clang.

### Исправлено после первой сборки на VS 2022

Первая сборка в VS 2022 упала на `fx_spectre.h`, `fx_spectre_classic.h` и
`fx_comb.h` (`C2039/C3646/C2065` про `nova::fx::...`, затем `fatal error C1003`).
Причина: при обёртке `#pragma GCC diagnostic` получился вложенный
`#if defined(__GNUC__)`, и `#include` сторонних заголовков MonoJuice оказался
внутри этой ветки. GCC/Clang её выполняли, MSVC — нет, поэтому типы
`MDCTPlans`, `Spectre`, `SpectreSettings`, `CombColour`, `CombSettings`,
`OdinSettings`, `ColourSettings` вообще не были объявлены.

Исправление: `#include` вынесены из условных блоков (внутри — только
`#pragma`), плюс `fx_spectre.h` и `fx_spectre_classic.h` теперь сами включают
`core/dsp.h` и не зависят от порядка подключения. Проверено симуляцией
MSVC-ветки (`__GNUC__`/`__clang__` не определены): 0 ошибок, все 263
DSP-проверки проходят.

Если сборка всё же падает — пришлите вывод консоли целиком, поправлю.

## 10. Поведение при ошибке: окно не закрывается

Раньше при любой ошибке скрипт делал `exit /b 1`, и окно, запущенное двойным
кликом, схлопывалось — сообщение об ошибке прочитать было нельзя. Теперь:

* **любая ошибка** (нет CMake, нет git, ошибка конфигурации, ошибка компиляции,
  не найден артефакт, не удалось скопировать бандл) выводит блок

  ```
  ============================================================
   BUILD FAILED: <причина>
  ============================================================
   Full build log:
     <папка>\build-vs2022\last-build.log
  ...
   The window stays open. Press any key to close (or set OROGEN_NO_PAUSE=1)...
  ```

  и ждёт нажатия клавиши;
* **весь вывод сборки** (`cmake --build`) дополнительно пишется в
  `build-vs2022\last-build.log` — при обращении достаточно приложить этот файл;
* при **успехе** окно закрывается само, но только если скрипт запущен из уже
  открытой консоли. При двойном клике из проводника оно тоже ждёт Enter, чтобы
  успеть увидеть путь к бандлу;
* для CI и планировщика: `set OROGEN_NO_PAUSE=1` — пауз не будет ни на ошибке,
  ни на успехе, код возврата остаётся прежним (`0` / `1`).

В PowerShell-скрипте то же самое: `-NoPause` отключает ожидание, на ошибке
печатается путь к `last-build.log`, а на успехе Enter ждётся только при запуске
двойным кликом (определяется по родительскому процессу `explorer`).

### Как это проверено

Скрипт прогнан в эмуляторе `cmd` (wine 10) с подставным `cmake.exe`, который
либо выдаёт ошибки компилятора, либо создаёт дерево бандла:

| сценарий | ожидание | результат |
|---|---|---|
| ошибка сборки, паузы включены | окно ждёт, код 1 | ждёт (тест оборван по таймауту), код 1 |
| ошибка сборки, `OROGEN_NO_PAUSE=1` | выход сразу, код 1 | код 1 |
| неверная конфигурация (`Debugg`) | `BUILD FAILED: Unknown configuration`, код 1 | так и есть |
| успех, паузы включены | окно ждёт Enter | ждёт |
| успех, `OROGEN_NO_PAUSE=1` | выход, код 0 | код 0 |
| содержимое `last-build.log` | весь вывод сборки | строки `error C2065` на месте |

PowerShell-скрипт проверен парсером PowerShell 7.4 (`Parser::ParseFile` — 0
ошибок) и прогоном: при отсутствии CMake печатается тот же блок `BUILD FAILED`
и код возврата 1. Попутно исправлено: если переменная `ProgramFiles(x86)` пуста,
`Join-Path` бросал исключение и сообщение об ошибке терялось.
