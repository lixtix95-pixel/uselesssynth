# OROGEN — VST3-обёртка

Текущая локальная ревизия: 30.10.2026; исторические замеры отдельно помечены датой.

## Текущая проверка GUI и VST3

Динамические контролы оверлея PARAMS теперь находятся в `OwnedArray`;
привязки APVTS снимаются до удаления самих контролов. До исправления при
закрытии редактора оставались **298/298** объектов, после — **0/298**.
Оставшиеся таймеры могли обращаться в выгруженную VST3-библиотеку: в
проверенной Linux Clang-сборке это воспроизводилось как падение при смене
инстанса. Внешний VST3-хост теперь повторяет **6/6** циклов открытия редактора,
выгрузки и обработки очереди сообщений; отдельный `test_plugin --lifetime-only`
проверяет 298 контролов через `Component::SafePointer`.

Полный Release `test_plugin` с native X11: **200/200**, DSP: **341/341**,
внешний хост stripped VST3: **45/45**. Два сценария фабричного Choir через
VST3 на 48 кГц, MIDI 60, без FX-миксов и с компрессором 1:1: пик выхода
**0.356468 / 0.821370**, 0/96000 отсчётов достигают 0.98; другие настройки
этим не гарантируются. Контроль Granular на 96 кГц через хост и MIDI: ошибка
**−13.2960 → +0.3787 цента**. Исправлен также скачок нормировки синтетических
источников короче 10 мс; пользовательская загрузка файлов в GUI не заявляется.
Windows/MSVC и конкретная DAW не проверялись.

Первый шаг, на котором проект перестаёт быть набором стендов: **тот же DSP-код
собирается как VST3** и открывается в DAW. Ни одна строка DSP не переехала и не
продублирована — движки, голос, патчер и эффекты подключаются из `orogen-dsp`
как заголовки.

```

├── CMakeLists.txt              JUCE через FetchContent (или -DOROGEN_JUCE_PATH)
├── src/plugin/
│   ├── Params.h                все параметры хоста — таблицами
│   ├── PresetJson.h            Patch + FxChain::Settings ⇄ JSON
│   ├── PluginProcessor.{h,cpp} AudioProcessor: MIDI, задержка, пресеты, состояние
│   └── PluginEditor.{h,cpp}    вкладки A–H / FX / Global, контролы из таблиц
├── tools/render_plugin.cpp     офлайн-рендер через сам плагин
└── tests/test_plugin.cpp       стенд параметров, аудио, пресетов и GUI
```

## Что делает обёртка

| подсистема | решение |
|---|---|
| Параметры | `AudioProcessorValueTreeState`, **298**: SLOT 168 + FX 84 + MOD 24 + ARP/LFO 15 + GLOBAL 7 |
| Движки | 9 типов в списке `TYPE` каждого слота: Wavetable, FM, Harmonic, Sample, Granular, Modal, Resynth, Organics, **Chop** (слайсер, итерация 12) |
| MIDI | по сэмплам: note on/off с velocity, all-notes-off, CC1 → мод-вход, CC64 < 64 → снятие нот, pitch wheel → мод-вход |
| Задержка | `setLatencySamples (FxChain::latency())` из message thread через `AsyncUpdater`; **1024** базовая (Robin), 5120 при Spectre с окном 3 |
| Шины | выход stereo или mono, входов нет (инструмент) |
| Пресеты | 7 фабричных (те же, что в стендах, включая «Chop Break») + файлы `.orogenpreset` (JSON) |
| Состояние | XML от APVTS + имя патча |
| Хвост | `getTailLengthSeconds() = 12` |

### Ключевое архитектурное решение

`Patch` и `FxChain::Settings` — источник истины, параметры — их автоматизируемое
зеркало. Пресет приходит как JSON **структур**, а не как набор значений
параметров, поэтому:

* новый параметр не ломает старые пресеты (читаем по имени, отсутствующие берут
  значение по умолчанию);
* то, что слышно в DAW, совпадает с офлайн-рендером стенда — это доказано
  нулевым тестом, а не на слух.

## Три бага, найденных при сборке обёртки

Все три — в DSP, а не в JUCE; первые два видны только при таком порядке вызовов,
какой делает хост.

1. **`FxChain::set()` до `prepare()` — segfault.** Плагин обязан заполнить
   параметры до того, как хост вызовет `prepareToPlay()`, а
   `SpectreFx::setWindow()` сразу шёл в `Spectre::reset()`, который обращается к
   ещё не посчитанным планам MDCT. Теперь `apply()` в `fx_spectre.h` и
   `fx_spectre_classic.h` ничего не делает до `prepare()`.
   Заодно исправлено в `orogen-dsp` — стенды этого не ловили, потому что всегда
   звали `prepare()` первым.
2. **`getRawParameterValue()` возвращает `nullptr` для списков и флагов.**
   Это API только для параметров, созданных самим APVTS; `AudioParameterChoice`
   пришлось читать через `RangedAudioParameter::convertFrom0to1 (getValue())`.
   Если бы не проверка «каждый id найден», это выглядело бы как «эффекты не
   включаются» без единой ошибки.
3. **`FxChain::set()` на каждый блок — это другой звук.** Плагин поначалу
   собирал `Patch` и вызывал `setPatch()/setFx()` в каждом `processBlock()`.
   `setFx()` переустанавливает размеры линий задержки и зеркал реверба, и
   повторный вызов менял результат. Теперь есть хэш значений параметров
   (`hashParams()`, FNV-1a по 52 float-параметрам эффектов) и структуры применяются только при
   реальном изменении. Нулевой тест после этого — ровно 0.0.

## Аудио-поток

`processBlock` не аллоцирует и не строит `juce::String`: все указатели на
параметры кэшируются в конструкторе и считываются на блок; при расчёте хэша
также читаются значения. Смена типа подготавливает движок в message thread;
аудиопоток подхватывает указатель, а старый объект удаляется из retire bin вне
аудиопотока. Счётчик аллокаций в `test_instrument` проверяет этот путь.

## Мод-матрица в обёртке

8 маршрутов × 3 параметра (`mod1_src`/`mod1_dst`/`mod1_amt` … `mod8_*`) = 24
параметра. Два перечисления (8 источников, 8 назначений) читаются через
`convertFrom0to1`, величина — обычный float −1…+1, где 0 = маршрут выключен.
Маршруты входят в `Patch::routes[]`, поэтому одинаково работают и в плагине, и в
стенде; в JSON-пресет пишутся массивом `routes`.

Колесо высоты больше не «подмешивается» в мод-вход: `pitchBend` идёт в
`Patch::bend`, то есть становится отдельным источником матрицы («Bend»).
Старое поведение (bend → modWheel) сохранено как запасной путь.

## Арпеджиатор в обёртке

`Arp` — единственный эффект набора, который стоит **до** голосов, поэтому он живёт
внутри `Instrument`, а не в `FxChain`. `processBlock` каждый блок собирает
`ArpSettings` из 7 параметров (`arpOn / arpMode / arpDiv / arpOctaves / arpGate /
arpSwing / arpLatch`), читает темп:

```cpp
double bpm = 120.0;
if (auto* ph = getPlayHead())
    if (auto pos = ph->getPosition())
        if (auto b = pos->getBpm()) bpm = *b;
inst.setTempo (bpm); inst.setArp (as);
```

События арпеджиатора рождаются в `Instrument::render()` (по одному сэмплу за
вызов), а не в MIDI-цикле: голоса запускаются уже внутри инструмента, поэтому
результат совпадает у плагина и у стенда (нулевой тест — 0.000e+00).

## Робин в обёртке

`Robin` (питч-шифтер) стоит в `FxChain` и **всегда** включён в тракт: его сухой
путь задержан на 1024 отсчёта, поэтому `FxChain::latency()` = 1024 + Spectre +
хорус. Так включение эффекта не меняет задержку и хост не дёргает транспорт.
Параметры: `fx_robinMix`, `fx_robinSemis` (±24), `fx_robinSize`, `fx_robinSpread`.

## Итерация 8: без аллокаций и с нормальным UI (25.10.2026)

### 1. Смена типа движка вне аудио-потока

Было: правка списка «TYPE» в слоте вызывала `makeEngine()` (то есть
`std::make_unique`) прямо в `processBlock`. Стало — три роли
(`orogen-dsp/src/instrument/engine_swap.h`):

| кто | что | аллокации |
|---|---|---|
| message thread, таймер 30 Гц | `Instrument::stagePatch()` строит движок в `pending[i]` и публикует его битом в атомарном `pendingMask` | да — и только здесь |
| аудио-поток | `Instrument::applyPatch()` меняет `unique_ptr` (только указатели) и отдаёт старый движок в retire bin | **нет** |
| message thread | `drainRetired()` удаляет заменённые движки | да |

Если в retire bin нет места, обмен откладывается на следующий блок: звук
остаётся прежним, а не «пропадает».

Замер (стенд `test_instrument`, блок «Смена типа движка»): счётчик
`operator new/delete` по потокам, 2 с рендера, параллельный поток сделал
**142 смены типов** (2 200 подмен слотов):

```
message-поток: 142 смены, 2 237 аллокаций (это норма)
аудио-поток:   0 аллокаций, подхвачено слотов 2 230
живых движков после уборки: 128  (16 голосов × 8 слотов)
NaN 0 · CPU 20 % (16×8) / 31 % (8×3) — не изменился
```

Побочно найден второй источник аллокаций в аудио-потоке: `bodyLevel()`
грануляра копировала огибающую в `std::vector` при каждом `prepare()`. Медиана
теперь считается один раз при сборке банка (`OneShot::bodyRms`).

### 2. Редактор

Интерфейс переделан по присланному макету — один экран 1280×800, тонкие линии,
свечение кривых, кольцевые ручки с насечками (`docs/ui_main.png`):

* **шапка** — логотип, полоса MASTER, четыре индикатора маршрутов мод-матрицы
  (горят, когда `modN_amt != 0`), LOAD/SAVE пресета (`.orogenpreset`);
* **левый рейл** — 8 карточек A–H: буква, LED включения (яркость = реальный
  уровень слота из `EngineBank::slotLevelsDb`), иконка движка, мини-волна его
  формы, два слайдера — LEVEL и TUNE. Клик по карточке выбирает слот;
* **центр** — дисплей с **настоящей** формой волны выбранной таблицы
  вейвтейбла (данные `WavetableBank`, кадр считается из `p0`/`p1`), три дорожки
  мод-редактора (8 маршрутов · LFO 1 shape/amount · ADSR выбранного слота),
  три пары «ручка + вертикальный слайдер» (CUTOFF/RESO, SHAPE/P2, LEVEL/DETUNE)

## LOAD / SAVE и банк в одном меню

Кнопки LOAD и SAVE в шапке работали только с файлом одного патча, хотя банк
уже был в API. Теперь левый клик — как раньше (диалог патча), **правый клик —
меню**: `Save patch…` / `Save bank…` / `Save bank (quick)` и, соответственно,
`Load patch…` / `Load bank…` / `Load bank (quick)`. «Quick» пишет и читает
фиксированный файл `OROGEN/bank.json` в каталоге данных приложения — без
диалога, одним пунктом.

Замер: банк `~/.config/OROGEN/bank.json`, 86 966 байт, программа «QUICK TEST»
получила индекс 8, после загрузки банка и выбора программы `sB_cutoff`
возвращается 0.100 → **0.800**.

Ещё раз про семантику: банк — это **список программ** (патч + настройки FX).
Порча одного лишь параметра в живой сессии банком не откатывается, потому что
этот параметр ещё не стал программой. Первая версия теста падала ровно на
этом (`sB_cutoff` 0.100 → 1.000, то есть вернулось значение программы 0);
правильный сценарий — сохранить патч как программу, потом возить банк.

## Анимации (блок 11 `test_plugin`)

Всё «живое» на экране считается от одной фазы — времени с момента создания
редактора. Фазу можно выставить руками (`setAnimationPhase`), поэтому кадр
воспроизводим побитово, а тест и `render_ui` снимают один и тот же кадр.

| что двигается | как |
|---|---|
| рамка выбранного слота в рейле | дыхание яркости 0.55…1.0, период 2 с |
| LED первых четырёх маршрутов в шапке | пульс с задержкой 0.18 с на маршрут |
| чипы FX | включённый чип подсвечивается волной, сдвиг 0.12 с по индексу |
| «кабели» между карточками колонки | комета с хвостом, у соседних кабелей сдвиг фазы — бежит волна |
| дорожка LFO 1 | playhead по кривой, частота берётся из `lfo1_rate` |
| векторный блок | гало вокруг точки дышит 18…22 px |

## Переходы, hover и реальный Morph (блоки 14–15)

**Переходы.** Страницы карточек FX и MOD MATRIX въезжают на 26 px с ease-out
за 0.14 с; направление вперёд сохраняется и при переходе с последней страницы
на первую. Страницы чипов FX и вкладки/секции PARAMS плавно проявляются.
Переключатель `Animations: off` отключает переходы: текущий сдвиг немедленно
сбрасывается, новая страница сразу полностью видна. Доступность параметров не
зависит от анимации. `docs/ui_transitions.gif` — реальные кадры переключения
FX-страницы и наведения на ручку, снятые `render_ui`.

**Hover.** Реальные `mouseEnter`/`mouseExit` обрабатываются для центральных,
нижних и малых кольцевых ручек в карточках. При включённых анимациях подсветка
плавная (~133 мс при 30 Гц), при выключенных — мгновенная. Тонкое белое кольцо
видно и когда ручка выставлена на 100 %. На макете размером 1280×800 координаты
основных областей не менялись.

**Что показывает дисплей.** Дисплей — не поток с выхода хоста, а синтетическая
нота **C4 / MIDI 60**, velocity 1, с нормировкой пика и удалением DC. В режиме
Stack он показывает только выбранный слот; в Morph и Split — фактическую смесь
включённых слотов, используя их реальные движки, параметры, фильтры, уровни,
панораму, конверты, зоны клавиатуры и данные модуляции из `collectPatch`.
Это рендер `Voice` **до мастер-FX и громкости**, а не итоговый осциллограф
сигнала DAW; другая нота, velocity, модуляция во времени и эффекты могут дать
другой звук. Названия движка и фильтра в подписи относятся к выбранному слоту,
даже когда график показывает смесь. Вся тишина (выключенный слот/вне зоны)
отображается без фиктивного сигнала.

Предыдущее сравнение `Stack`/`Morph` проходило по отличию картинки, хотя
превью подставляло настройки по умолчанию для соседних слотов. Это исправлено:
берётся снимок реального патча. Значение Morph 0.071 соответствует примерно
середине **A/B** (`0.071 × 7`); 0.5 — между D и E. Кэш учитывает все
участвующие поля. Отрисовка явно инвалидирует область дисплея при готовности.

Расчёт выполняется в отдельном низкоприоритетном потоке, не в аудио- или
GUI-потоке: банк контента строится один раз, частые запросы объединяются,
устаревший результат не публикуется. После первого старта в 0.5 с звука
(24 000 отсчётов при 48 кГц, включая атаку) выбирается наиболее громкое окно
**4096 отсчётов = 85.3 мс**, шаг 512. Выбор окна позволяет видеть редкие зёрна
Granular и короткие удары CHOP. Далее строится 512 min/max колонок единым
кэшированным `Path`. Подписи `STACK / SLOT`, `MORPH / MIX`, `SPLIT / MIX`,
`C4 NO FX` показывают границы этого превью; пока идёт пересчёт — `UPDATING`.

## Банк программ

Раньше набор программ жил только в памяти: `changeProgramName()` переименовывал
программу до перезапуска, а хостовый «Save preset» сохранял один патч.
Добавлены `bankToVar()` / `saveBankFile()` / `loadBankFile()` / `addProgram()`:

* банк — один JSON (`{"format":"OROGEN bank","programs":[ … ]}`, внутри каждого
  элемента то же, что в файле пресета: `patch` + `fx`);
* `loadBankFile()` разбирает **весь** файл до того, как что-то менять, поэтому
  битый банк не оставляет плагин без пресетов;
* одиночный `.orogenpreset` тоже принимается — как банк из одной программы;
* `addProgram()` снимает текущие параметры в новую программу (это же решает
  задачу «сохранить то, что сейчас нарулено»).

Проверки (блок 3b `test_plugin`, 8 программ, файл 77 379 байт): правки
`fx_chorusDelay` 91, `fx_glitchFold` 2.5, `gl_glide` 0.42 переживают круг с
расхождением 0.000; переименование переживает банк; битый банк отвергается,
программы остаются целы; одиночный пресет грузится как банк из одной программы.

## Granular и общий MIP — повторная доводка 29.10.2026

Granular запускает первое зерно сразу и фиксирует нормировку действующих зёрен
при автоматизации Density; Position и границы sinc учитывают длину реального
зерна. На дробном pitch используется 64-tap полосовой sinc, чтобы устранение
alias не срезало слышимую полосу. Исправлены фазовая задержка MIP, масштаб
нечётных буферов и огибающая очень короткой записи. Органическому движку
исправлена склейка петли и защита короткой огибающей — подробности и ограничения
в `orogen-dsp/ENGINE-05-granular.md` и `ENGINE-08-organics.md`.

Release-прогон Linux 29.10.2026: **310 OK / 0 FAIL** в 11 отдельно запущенных
DSP-тестах, **185 OK / 0 FAIL** в `test_plugin`, **32/32** во внешнем JUCE
VST3-хосте. При MIDI Note On Granular выход превысил тестовый порог на
отсчёте **1045** при 48 кГц, из них **1024** — постоянная latency ROBIN;
остаток **0.438 мс**. После этой задержки изменение Density 0→1 не изменило
текущий сигнал в окне 128 отсчётов (max Δ **0.00000000**); последующие 107 мс
дали ΔRMS **0.033081**. Переключение Wavetable→Granular в GUI на удержанной
ноте без второго Note On: RMS после **0.03420**, ΔRMS **0.07139**.

При дробных rate 17.6/20/24/48/150 тон 14.4 кГц удерживается в пределах
**1.49 дБ** от низкой опоры, alias тона на 1% выше Найквиста не выше
**−66.80 дБ** на этих тестовых входах. Сырые пики некоторых источников
превышают 1.0 во float; без дополнительного headroom проигрыватель может их
срезать. GUI сохранил макет и доступность параметров, но новые алгоритмы
Granular и общего MIP могут изменить звучание старых проектов; не заявляется
побитовое совпадение с ними. Отдельно исправлен разрыв существующего FX-лимитера
на 0.98: при входе 0.97999→0.98001 скачок выхода уменьшился с 0.20540941 до
0.00001001, порог и уровень движка не менялись; ранее перегруженные проекты
могут звучать иначе. Проверки реальной DAW и Windows не проводились.
