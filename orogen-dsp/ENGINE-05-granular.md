# Движок 05 — Granular

Гранулярный синтез из восьми процедурных one-shot'ов общего банка Sample.
Одновременно — до 12 зёрен на слот/голос, окно Ханна, длина 8…220 мс,
плотность 4…90 зёрен/с, случайный разброс высоты до ±7 полутонов. Четыре
макроса: **Position / Size / Density / Spread**. Отдельная вероятность реверса
для каждого нового зерна: `PARAMS → SLOT → A…H → Grain Reverse` (0…1).
Она не переопределяет Spread и не действует на остальные типы движков.

```bash
cd orogen-dsp
make build/test_granular && ./build/test_granular
make build/render_granular_raw build/render_granular_transient build/render_granular_pitch
make build/render_granular_short build/analyze_choir_source
make build/test_vocal_vibrato build/test_granular_vocal build/render_vocal_source
./build/test_vocal_vibrato && ./build/test_granular_vocal
mkdir -p audio
./build/render_vocal_source audio/choir-source.wav 2
./build/render_granular_raw audio/granular_raw.wav 0
./build/render_granular_transient audio/granular_transient.wav
./build/render_granular_pitch audio/granular_pitch.wav
./build/render_granular_short audio/granular_short.wav
./build/analyze_choir_source
# Одинаковые настройки, различается только вероятность реверса:
make build/render_granular_reverse

./build/render_granular_reverse audio/mixed.wav 0.5 0

make build/bench_granular_reverse
./build/bench_granular_reverse  # запускать отдельно от сборки
```

## Вокальные источники: ограниченная частота вибрато (31.10.2026)

`Choir Ah` и `Vox Ah` использовали фазу `f0 * t * vib(t)` вместо интеграла
мгновенной частоты. Производная содержит добавочный член `t * vib'(t)`, поэтому
мнимая глубина вибрато росла по ходу исходника. Фаза теперь интегрируется
аналитически в `src/engines/vibrato_phase.h`; исходные rate/depth, форма
огибающей, форманты, калибровка банка, усиление движка и лимитер не менялись.

Независимый замер периодов исходника при MIDI 45 / 110 Гц, 48 кГц:

| источник | интервал измерения | до | после |
|---|---|---|---|
| Choir | 1.4–1.8 с | 86.734…134.444 Гц | 109.561…110.435 Гц |
| Vox | 1.4–1.8 с | 110.176…111.453 Гц | 109.975…110.221 Гц |

Максимальная ошибка относительно заданной мгновенной частоты на 0.12–1.9 с:
Choir **25.767 → 0.006 Гц**, Vox **1.401 → 0.006 Гц**. На выходе **самого
Granular**, одно зерно, root note, 4 позиции и оба направления: Choir
**98.933…134.444 → 109.560…110.438 Гц**, Vox **109.901…111.452 →
109.779…110.218 Гц** (48 кГц). Аналогичные проверки прошли на 44.1 и 96 кГц;
`test_vocal_vibrato` и `test_granular_vocal` дают **13/13**, NaN/Inf 0.

Банк общий с Sample, Organics и Resynth. Поэтому старые проекты с Choir/Vox
могут **слышимо измениться во всех четырёх движках**; ID и значения параметров
не менялись. Шесть остальных фабричных источников на 48 кГц имеют прежние хеши
всех MIP-отсчётов; отдельные рендеры Fm Tine четырёх движков побайтно
совпали с предыдущей ревизией. Это ограниченная проверка совместимости, не
гарантия идентичности всех настроек и пресетов. В корне workspace сохранены
`OROGEN-choir-source-before.wav` / `...-after.wav`: источник до движка, 48 кГц,
mono float32, пики 0.95, без пост-нормировки и FX. Они демонстрируют высоту,
а не итоговый выход плагина.

**Headroom не исправлен:** в том же шестисекундном сухом тесте Granular/Choir
пик **1.312574 → 1.260694**, **310 из 287989** отсчётов после исправления
превышают единицу; Vox после — **1.171095**. Reverse Choir 0/50/100% —
**1.131742 / 1.134594 / 1.165655**. Это float-сигнал до фильтров/FX; он сам
по себе не доказывает клиппинг в DAW, но WAV может обрезаться проигрывателем.
Исправление высоты не выдаётся за исправление пиков. Ни лимитер, ни пост-уровень
для сокрытия пиков не добавлялись.

## Независимые потоки Reverse (31.10.2026)

Раньше каждый слот и каждая нота начинали RNG направления с одной точки: при
одинаковых слоях на 50% зёрна шли в reverse синхронно. Теперь `Voice` задаёт
детерминированный seed из номера note-on и слота A–H; он используется **только**
для направления, не для Position, Spread и времени рождения. Тот же serial и
слот повторяют ту же последовательность; свободный `GranularEngine` вне Voice
оставлен с прежним начальным seed. Это не новый параметр хоста.

На восьми потоках по 360 зёрен доля обратных составила **46.67…55.00%**,
попарное совпадение направления с A — **50.00%**; max Δ границы **0.000244**
отсчёта, Δ скорости 0, рассинхронизация рождения 0. Два идентичных слоя A/B,
панорамированные L/R, до/после при 50%: ΔRMS/RMS **0 → 0.991847**. В настоящем
VST3-хосте: при 0/50/100% **0.0000002 / 0.9934010 / 0.0000002**, корреляция
L/R **1.00000 / 0.50685 / 1.00000**. Для 0% и 100% стерео-WAV в контрольных
сценариях побайтно совпали с предыдущей ревизией.

В корне workspace — `OROGEN-granular-stereo-before.wav` и `...-after.wav`:
около 4 с, 48 кГц stereo float32, Reverse 50%, идентичные Fm Tine в A/B,
отдельный `Voice` с фильтрами и встроенным soft clip, без мастер-FX и
пост-нормировки. L/R корреляция **1.000000 → 0.444850**, пик **0.154438 →
0.154639**, NaN/Inf 0. Конец обрезан около нуля; статистика измерялась до
обрезки. Это диагностический пример, а не обещание ширины для любого патча.

Совместимость: сохранённые 306 ID и значения не менялись, но патчи с
`0 < Grain Reverse < 1` могут воспроизводить другую последовательность
направлений, чем в предыдущей версии. На 0%/100% направления не изменились.

## Реверс зёрен (30.10.2026)

Новый независимый параметр A–H с default 0 назначает вероятность обратного
чтения **при рождении** зерна; автоматизация не меняет направление уже играющих
зёрен. Положительная абсолютная скорость по-прежнему выбирает безопасный MIP
и 32/64-tap sinc. Reverse начинает на верхней границе того же участка и шагает
назад с `double`-позицией. Отдельный RNG не сдвигает Spread и Position.
Огибающая учитывает Hann² и оба конца обратного прохода; при Reverse=0
сохранён прежний расчёт, кроме описанной ниже защиты от заворота за край.

В синтетическом тесте с громкой атакой у нижнего края исходная реализация
реверса давала gain в **3.998991 раза** выше, чем на том же прямом участке.
Теперь **1.000000 раза**; при громком верхнем крае отношение **0.250000** —
атака учитывается в обоих направлениях. Это поправка оценки огибающей внутри
движка, не регулировка общего усиления, FX, лимитера или нормировка файла.

Фиксированный seed: 0/360, **175/360** (48.61%) и 360/360 обратных зёрен при
0/50/100%; повторный прогон 50% совпал побайтно. Позиции и скорости независимы
от RNG направления: максимальная разница границы 0.000244081 отсчёта,
скорости — 0. При переключении 0→100% первое новое reverse-зерно появилось
через 433 отсчёта, уже звучащее зерно не изменилось. Два 6-с контрольных
рендера при 0% побайтно совпали с версией до реверса (при тех же флагах).

Пять тестов высоких |rate| = 17.6/20/24/48/150: worst alias у Найквиста
**−66.09 дБ**, худшее |Δ| 14.4 кГц **2.30 дБ**; допуски сохранены прежние.
На 26-с синтетическом источнике 96 кГц фактический выход обратного зерна
4756.828071 Гц при эталоне 4756.828308 Гц: **−0.000086 цента**.
ASan/UBSan: 432 сценария, 3114 зёрен/1521 обратное, 0 выходов за границы,
ошибок знака и NaN/Inf; дополнительно 216 сценариев коротких источников и
прямое/обратное чтение длинных источников. При 96 кГц накопление float-фазы
иногда завершало длинное зерно позже `dur`: в синтетическом тесте, прижатом
к краю, sinc до поправки заворачивался на другой конец 1 раз при reverse и
3 раза при forward. Защитный путь sinc не выходил за выделенную память, но
такое чтение могло дать артефакт. Теперь следующее зерновое чтение останавливается
перед границей: 4/4 проверки forward/reverse с 32/64-tap, заворотов 0,
минимальная фаза остановки **0.99989158**. `test_granular` **49/49**,
`test_granular_reverse` **8/8**, весь DSP **354/354** в 12 наборах.
Отдельный Release-бенчмарк на этой машине, 16 голосов / 48 кГц / 3.2 с,
медиана трёх прогонов при Reverse 0/50/100%: **17.86 / 17.64 / 17.30% ядра**.
Это конкретные параметры и машина, не гарантия для других систем.

Три ненормированных WAV из Fm Tine, около 6 с, 48 кГц mono float32, без FX;
конец обрезан на переходе через ноль без изменения отсчётов. 0/50/100% имеют
пики **0.348287 / 0.363890 / 0.329950**, RMS **0.122525 / 0.127882 / 0.129277**.
Для сравнения, до проверки обоих краёв 6-с рендер reverse имел пик 0.544006,

## Короткий источник и порог огибающей 10 мс (предыдущая ревизия 30.10.2026)

При подготовке источника короче 10 мс RMS всей записи вычислялся корректно, но
огибающая оставалась пустой. В `spawn()` запасное значение `envAt()` было 1.0,
то есть не RMS записи. Теперь Granular использует вычисленный `bodyRms`, только
если в записи нет 10-мс ячеек. Нормировка источников с непустой огибающей,
`kGainTrim`, лимитер, уровни и параметры не менялись.

Независимый тест рендерит первое зерно синуса 1 кГц на 44.1/48/96 кГц;
длины на один отсчёт меньше и ровно 10 мс, входные амплитуды 0.03/0.30/0.80
(9 пар). Худший скачок RMS **12.069 → 0.027 дБ**, gain зерна **12.051 →
0.009 дБ**. Для одинакового 5-мс сигнала с амплитудами 0.30 и 0.80 разница
уровня **7.102 → менее 0.001 дБ**. Тишина остаётся тишиной, NaN/Inf нет.
Это синтетические источники внутри DSP-теста: пользовательский импорт в GUI
**не реализован и не заявляется**; фабричные one-shot имеют длину 2 с.

`render_granular_short` выдаёт 4 с диагностических импульсов, чередуя источники
479/480 отсчётов, 48 кГц, mono float32. В корне workspace сохранены файлы
`OROGEN-granular-short-before.wav` и `OROGEN-granular-short-after.wav`, оба
получены с одинаковыми флагами компилятора без FX, лимитера и нормировки файла.
За первые 10 мс каждого импульса RMS: **0.02865919/0.11495654** до и
**0.11463676/0.11495654** после; Δ **12.06540 → 0.02420 дБ**. Это проверка
граничного поведения, не музыкальное демо. В обоих файлах импульсы из
480-отсчётного источника побайтно совпадают. При одинаковых флагах компиляции
отдельный 6-с фабричный рендер Choir до/после также побайтно совпал: эту
поправку нельзя выдавать за исправление Choir/headroom.

ASan/UBSan: дополнительно **108** сценариев границы на 44.1/48/96 кГц,
**1008 зёрен**, 0 небезопасных чтений и ошибок тишины/NaN. Всего Granular
**44/44**, полный DSP **341/341**; CPU отдельного Release-прогона полного
набора — **18.5% ядра / 16 голосов** на данной машине.

Granular/Choir, 48 кГц, 2 с, P1/P2/P3/P4 = .35/.45/0/.20, Level 1,
компрессор 1:1 и FX mix 0, постоянная latency 1024: при Patch Gain .67,
Master .8, Pan по центру пик выхода **0.356468**, stereo RMS **0.036034**;
при Gain 1, Master 1, Pan −1 — пик **0.821370**, RMS **0.063855**. В обоих
сценариях **0/96000** отсчётов достигают 0.98, NaN 0. Это результаты двух
конкретных настроек, а не гарантия отсутствия перегруза в других проектах;
сырой float-пик **1.312574** движка при другом рендере остаётся открытым.

В самом фабричном источнике анализ периодов на 48 кГц обнаружил дополнительную
проблему высоты: при root MIDI 45 (110 Гц) в интервале записи 1.4–1.8 с
**86.734…134.444 Гц**, тогда как множитель `vib` отдельно задаёт диапазон
109.560…110.440 Гц. Фаза имеет вид `f0 * t * vib(t)`, поэтому её производная

движка/FX, не доказательство причины пика или клиппинга VST3. Общий банк
источников не менялся: он используется и другими движками; исправление этой
части требует отдельной проверки совместимости и пока не выполнено.

## Точность высоты на поздней позиции (30.10.2026)

Курсор зерна раньше накапливал дробный шаг в абсолютной координате `float`.
Из-за округления при каждом прибавлении частота зависела от позиции в записи.
Курсор переведён на `double`; в Granular-пути MIP целый индекс отделяется от
дроби до преобразования дроби в `float`. Другие движки продолжают использовать
прежний float-путь. Скорость отдельно взятого зерна по-прежнему фиксирована до
конца его окна. Уровень движка, лимитер и параметры не менялись.

На фабричных источниках 2 с, при 44.1/48/96 кГц и 15 комбинациях, максимальная
ошибка шага **13.686319 → менее 0.000001 цента**; на синтетическом источнике
26 с при 96 кГц — **301.954968 → менее 0.000001 цента**. Независимая проверка
интерполяции синуса 8 кГц на позициях 0.05/24.5 с: относительная RMS-ошибка
**0.00011157 / 0.03778142 → 0.00004520 / 0.00004520**.

`render_granular_pitch` даёт прямой 3-с WAV, mono float32, без FX, нормировки
и лимитера. Синус в источнике 26 с, Position 0.95, MIDI 36, 96 кГц, эталон
**297.301779 Гц**: до исправления **250.000073 Гц (−299.9995 цента)**, после
**297.301814 Гц (+0.0002 цента)**, NaN/Inf 0. Готовые файлы до/после лежат в
корне рабочего пространства; в исходниках рендерится текущее поведение.

Через MIDI и собранный VST3 в отдельном JUCE-хосте, фабричный Sub Bass и
MIDI 37 на 96 кГц: **68.765502 Гц (−13.2960 цента) → 69.310817 Гц
(+0.3787 цента)** относительно 69.295658 Гц, после задержки ROBIN 1024
отсчёта. Это измерение всего проверяемого тракта, не внутреннего курсора.

ASan/UBSan: прежние 240 сценариев/3013 зёрен плюс на 26-с источнике быстрый
проход 15 зёрен и дробный медленный проход 48 зёрен на четырёх позициях;
небезопасных чтений и NaN/Inf **0**. Все 41 тест Granular прошли; в изолированном
Release-прогоне 16 голосов использовали **14.9% ядра** (зависит от машины).

## Нормировка перехода тихо → громко (30.10.2026)

Огибающая источника теперь оценивается на всём фактическом проходе зерна с
весом Hann², а не только по 10-мс ячейке у его старта. Значение фиксируется
при запуске зерна; звучащие зёрна не перенормируются скачком. Берётся максимум
начальной и взвешенной оценки, чтобы не усиливать затухание сильнее прежнего.
`kGainTrim` не менялся, дополнительного лимитера/нормировки WAV нет.

Синтетический тихий предудар с последующей атакой: RMS у старта **0.040941**,
взвешенный RMS **0.245196**. До исправления усиление зерна **2.682873** при
расчётном **0.611756**, пик **2.467303**; после — **0.598700** и пик
**0.550595**. `render_granular_transient` повторяет этот сигнал 4 секунды,
48 кГц mono float32: пик **0.550595**, RMS **0.133487**, без FX и нормировки.

На длинном проходе точечные пробы могли пропустить короткий всплеск. Банк
заранее строит префикс суммы энергии 10-мс ячеек; до 256 фазовых секций
интегрируют все ячейки внутри каждой, без аллокации и поиска по всему участку
в аудиопотоке. Hann² вычисляется в центре каждой секции, поэтому это **оценка**,
а не точный интеграл огибающей. Фабричные источники используют обычные частые
пробы; пользовательский импорт в GUI не заявляется.

Регрессия: реальная синтетическая запись **30 с**, проход зерна **12.544 с**,
всплеск 10 мс строго между соседними точечными пробами. До исправления gain
**6.000000 / 3.787366 = 1.58421** от независимого интеграла; после —
**3.787548 / 3.787366 = 1.00005**. ASan/UBSan отдельно проверяет источник
26 с, 15 зёрен, 0 небезопасных чтений и NaN. Это не гарантия headroom для
всех сигналов: проблема пиков Choir ниже остаётся открытой.

## Автоматизация Detune и Level (30.10.2026)

Detune теперь работает независимо от Spread: `Voice` задаёт каждому Note On
своё детерминированное случайное значение, а максимальный Detune 1 соответствует
диапазону **±10 центов**. У уже звучащего зерна скорость и MIP фиксированы до
конца окна; изменённые Detune или Pitch влияют на **последующие зёрна**, не на
текущее. Это сохраняет безопасные границы чтения и избегает скачка высоты внутри
зерна, но не является мгновенным изменением всех зёрен на удержанной ноте.

Внутренний множитель Level переведён на сглаживание без изменения калибровки:
при переходе 1→0 первый относительный скачок 0.600808→**0.002498**, установившееся
отношение RMS **0.400003**. Это внутренний множитель движка, не итоговый Level
слота: последний дополнительно управляет общим уровнем в `Voice`.

Проверено: Detune 0→1 при Spread 0 дал относительную ΔRMS **0.573440**;
на крайних значениях случайного отклонения измерено **−10 / +10 центов**.
Два Note On с одинаковыми настройками: ΔRMS **0.000000** при Detune 0 и
**0.644845** при Detune 1. На одной удержанной MIDI-ноте в AudioProcessor
автоматизация Detune дала ΔRMS **0.279707**. В тесте новое зерно появилось
через 434 отсчёта; rate старого остался **2.37841415**, новое получило +10 центов.
Это относится к данным сценариям, не к каждому случаю на каждом источнике.

Для проверки предельной автоматизации запустите `make asan-granular`: отдельный
стенд под ASan/UBSan прошёл **240 сценариев, 3013 зёрен, 0 небезопасных чтений,
0 NaN/Inf** (44.1/48/96 кГц, 5–2000 мс источники). Инструментированный CPU
не сравнивается с Release: санитайзеры существенно замедляют вычисления.

## Что исправлено (29.10.2026)

- Первое зерно запускается сразу после Note On, а не через период Density.
  Дальше в окне Ханна его амплитуда естественно нарастает.
- Уровень каждого зерна рассчитывается при его запуске по реальной длительности
  и перекрытию. Автоматизация Density не перенормирует уже звучащие зёрна
  скачком. Старый дополнительный множитель `sqrt(dur/want)`, из-за которого
  короткие зёрна гасились дважды, убран.
- Position относится к допустимым стартам внутри источника. Случайное смещение
  считается от реального размера зерна и отражается от краёв, вместо того чтобы
  перескакивать через всю запись.
- Скорость нового зерна задаёт его span. Границы включают каждый отвод sinc в
  реально читаемом MIP-уровне, а не только центральный отсчёт. Если источник и
  требуемая скорость не позволяют уместить даже минимальное зерно с запасом для
  sinc, зерно пропускается; это не алгоритм растяжения произвольно коротких файлов.
- MIP-уровни выровнены по фазе после децимации; позиция масштабируется ровно на
  `1/2^L` даже при нечётной длине. Максимум — 11 уровней при достаточной длине.
- При дробном pitch обычный выбор следующего MIP слишком сильно срезал верхние
  частоты: в Granular используется нижний MIP и 64-отводный полифазный sinc
  с верхней границей полосы, зависящей от скорости внутри октавы. Доступно 16
  диапазонов скорости; коэффициенты фиксируются на время зерна. На точных
  октавах и для замедления используется прежний 32-отводный sinc.
- Таблицы sinc и косинуса создаются при подготовке движка, не в первом `render`.
  Огибающая источника короче 10 мс может быть пустой: RMS такого источника
  рассчитывается безопасно по его отсчётам при сборке банка.

Общий MIP используется также в Sample/Organics/CHOP, поэтому его исправление
может изменить спектр прежних проектов. В Organics дополнительно исправлены
адрес начала кроссфейда петли, сохранение остатка шага и безопасность короткого
источника; это не полная переработка этого движка.

## Диагностический WAV без постобработки

`render_granular_raw` пишет mono IEEE float32 напрямую с выхода движка: без
фильтра слота, FX, нормировки, лимитера и изменения громкости после рендера.
В 2 секунды Density 0→1, в 4 секунды Position 0.35→0.90. Обрезка на последнем
переходе через ноль не меняет сохранённые отсчёты. Параметр Level = 1.

После pitch-исправления на одном и том же шестисекундном сценарии источник
**Fm Tine (0)**: пик **0.499138**, RMS **0.116721**, NaN 0. **Choir Ah (2)**:
пик **1.312574**, RMS **0.167717**, NaN 0; Vox Ah (6) — пик **1.166071**.
Float-сигнал выше 1
сам по себе не обрезан, однако обычный проигрыватель/ЦАП может его срезать.
Это ограничение headroom в сыром сигнале, а не доказательство клиппинга в DAW;
не следует считать такой WAV проверкой отсутствия клиппинга всего плагина.

После pitch-исправления в первые 2 с Choir **301 из 96000 отсчётов**
(**0.314%**) имеют |x| > 1. В дополнительной локализации предыдущей ревизии
в точке пика было активно одно зерно: значение источника
**0.54742**, локальный RMS **0.135588**, усиление зерна **1.039781**, общий
множитель движка 2.3; сумма до DC-фильтра **1.308776**. Крупные соседние
перепады в этом месте образуют гладкие периодические колебания, поэтому только
по max |dx| нельзя считать их одиночными щелчками. Причина высокого пика —
сочетание высокой пик-факторности фрагмента и RMS-калибровки; просто уменьшить
демо или спрятать пик лимитером — не исправление. Вопрос headroom остаётся
открытым: нельзя обещать отсутствие срезания при воспроизведении этого WAV.
Для прослушивания без срезания в этом сценарии пригоден Fm Tine; результаты
Choir/Vox приведены без сокрытия и требуют отдельной проверки уровней в тракте.
Старый `render_demo_granular` делает художественную балансировку и нормировку
демо и потому **не** используется для проверки ненормированных пиков.

## Ограничения

- Нет стерео-зёрен и freeze; пользовательская загрузка файлов не заявляется.
  Реверс работает для отдельных моно-зёрен. При недостаточной длине/слишком
  высоком pitch зерно пропускается.
- Пики >1 в отдельных сырых сценариях и перепады в некоторых исходниках
  Organics требуют дальнейшей проверки в тракте. Диагностический WAV обходит
  FX; в самом плагине сохранён существующий выходной лимитер. Его отдельный
  разрыв исправлен без изменения порога — это не исправление пиков движка.
- Интерфейс и ID параметров сохранены, но переработанное поведение Granular и
  общих MIP может изменить звучание ранее сохранённых проектов.
