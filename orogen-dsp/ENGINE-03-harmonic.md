# Движок 03 — Harmonic

Аддитивный синтез до 64 партиалов двумя путями: быстрым (серия Чебышёва)
и медленным (своя фаза у каждого партиала, растяжка по частоте).

```
make build/test_harmonic && ./build/test_harmonic
```

## Замеры

| проверка | результат |
|---|---|
| алиасинг (быстрый путь), ноты 45/57/69/81 | −90.1 / −92.9 / −88.0 / **−87.6** дБ |
| DC | 0.264·10⁻³ |
| RMS | 0.198 на всех трёх режимах (spread 0 / 0.5 / 1.0) |
| энергия выше 1 кГц (медленный путь, нота 57) | −3.3 дБ от энергии ниже 1 кГц |
| crest | 1.9 (быстрый) / 2.5 (медленный) |
| CPU | 14.8 % ядра на 16 голосов = **0.93 %/голос** (64 партиала) |
| число партиалов = `floor(0.45·48000/f0)` | 64/64/64/64/41/20/10 для нот 24–96 |
| стабильность | 10 с на 64 партиалах без дрейфа |

Демо: `audio/harmonic_demo.wav` — 20 с, 4 тембра (тёмный орган, пила,
расстроенный ансамбль, «стеклянный» с движением), пик 0.890, RMS 0.128,
центроид 1031 Гц. Спектрограмма `audio/harmonic_demo_spectrum.png` — видны
62–64 раздельных партиала на нотах 45–62.

## Два пути

**Быстрый** (spread ≈ 0): один фазовый аккумулятор и рекуррентность Чебышёва

```
sin((k+1)φ) = 2·cos(φ)·sin(kφ) − sin((k−1)φ)
```

Один `sin` и один `cos` на сэмпл при любом числе партиалов. Предел партиалов
считается от ноты: `P = min(64, floor(0.45·fs/f0))` — партиал выше Найквиста
не создаётся.

**Медленный** (spread > 0.02): у каждого партиала своя фаза и свой шаг,
частота растягивается `f_k = k·f0·sqrt(1 + B·k²)` (модель жёсткой струны).
Здесь спектр заведомо ингармонический — это и есть смысл параметра Spread,
поэтому метрика «вне k·f0» к нему неприменима (проверяется crest и RMS).

## Что было исправлено

1. **Растущий профиль `a_k = k^+0.2`** давал «жужжание» и crest 8.7 —
   звук с перегрузом. Только убывающий: `a_k = k^-(1.4 − 0.9·tilt)`.
2. **Чётные партиалы через ту же серию синусов** давали расфазировку —
   добавлена вторая серия (косинусы) для чётных и синусная для нечётных:
   алиасинг упал с −31.6 до −87.5 дБ.
3. **Motion как AM** создаёт сайдбенды ±(k·0.48) Гц: для 64-го партиала
   это ±30 Гц, что метрика считала алиасингом. В тестах `p[3] = 0`
   (движение проверяется по crest), в демо — включено.
4. Калибровка `kGainTrim` 0.62 → 0.42 → 0.28 по фактическому RMS.

## Что было исправлено (продолжение: три бага, найденных при сведении демо)

5. **Первый `prepare()` брал tilt в другой шкале.** В ветви `needSnap` стояло
   `clamp(p[0], −1, 1)`, в обычной — `clamp(p[0], 0, 1)·2 − 1`. Первый голос
   каждого пресета играл с tilt вдвое меньшим, чем все последующие: 12 дБ разницы
   по ВЧ на первой ноте. Теперь шкала одна.
6. **Медленный путь играл все 64 партиала на основной частоте.** В цикле стояло
   `pinc[k−1] = inc·stretch` — без множителя `k`. Все партиалы шли на f0 с
   микро-расстройкой: RMS 0.170 при спектре целиком ниже 1 кГц, энергия выше
   1 кГц — минус 73 дБ. Ни RMS, ни crest этого не ловили.
7. **Коэффициент растяжки был нефизичным**: `B = spread·0.0016` при k = 64 давал
   +72 % (полторы октавы) — 64-я гармоника вываливалась за Найквист. Теперь
   `B = spread·2·10⁻⁵` (максимум +5 % на 64-м партиале, как у реальной струны),
   и партиалы выше 0.45·fs не создаются вообще.

После исправления демо стало на 40 дБ ярче: центроид 354 → 1031 Гц,
энергия 1–3 кГц выросла с −48 до −10 дБ. В стенд добавлена регрессия
«медленный путь действительно даёт спектр выше f0» — она падает, если
частота партиала снова потеряет номер `k`.

## Что осталось за рамками

- Нет формантного фильтра поверх партиалов (в Terrain есть вокальные пресеты).
- Нет интерактивного морфинга профиля между двумя «картинками» спектра.
- Медленный путь при 64 партиалах — 3 % CPU на голос; в VST3 это ограничивает
  полифонию до ~8 голосов на инстанс.
