# Нагрузка: профиль и что удалось снизить (25.10.2026)

Вопрос был «как уменьшить нагрузку». Ниже — измерения до/после, а не оценки.
Все цифры получены на одном и том же стенде (48 кГц, стерео, эта песочница,
`-O2 -march=native`), между прогонами разброс ±20 %, поэтому сравнивать можно
только прогоны, снятые подряд.

## 1. Где нагрузка жила

Профиль по компонентам (стерео, 10 с аудио, % одного ядра):

| компонент | до | после |
|---|---|---|
| Shaper (tanh) | 0.2 % | 0.2 % |
| WDF-сатурация, 4x | **4.2 %** | **3.0 %** |
| Chorus / PingPong / Reverb / Plate | 0.2 / 0.1 / 0.2 / 0.3 % | без изменений |
| Eq | 0.5 % | 0.4 % |
| Dynamics + лимитер | 0.3 % | 0.2 % |
| FxChain целиком (drivе=tanh) | 0.6 % | 0.5 % |
| FxChain целиком (drivе=WDF) | **4.7 %** | **3.5 %** |

То есть FX — это ~3.5 % ядра, из которых 85 % приходится на один модуль (WDF).

Главная же нагрузка была не в эффектах, а в голосе: любая нелинейность
(`warp` / `fold`) включает оверсэмплинг, и стоимость голоса вырастала в 18 раз.

| путь wavetable-движка, 1 голос | до | после |
|---|---|---|
| чистый путь (warp = fold = 0) | 0.119 % | 0.079 % |
| warp 0.2 (4x) | 1.536 % | **0.672 %** |
| fold 0.15 (4x) | 1.553 % | **0.676 %** |
| как в `Init` (warp 0.2 + fold 0.15) | 2.275 % | **0.804 %** |
| fold 0.6 (8x) | 4.281 % | **1.700 %** |

## 2. Что сделано

### 2.1 Полуполосный дециматор (`src/engines/halfband.h`)

* буфер двойной записи (продублирован на `kSize`) — окно из `kTaps` отсчётов
  читается непрерывно, маска ушла из сэмплового цикла, компилятор векторизует
  свёртку;
* при срезе ровно 0.25 (`FcK = 250`) половина коэффициентов тождественно
  нулевая, `sin(πn/2) = 0` при чётном `n`: такие пары пропускаются
  (`if constexpr`), умножений вдвое меньше при **том же** фильтре;
* финальная ступень `decimC` 255 → 127 отсчётов при том же срезе 0.22:
  алиасинг не изменился вообще (см. ниже), стоимость упала на треть.

Проверка, что не сломали качество: алиасинг нелинейностей в стенде
**−74.12 дБ до и после** (было −74.06 дБ), по таблицам −78.5 дБ, по клавиатуре
−69.2 дБ. Дополнительно прогнан свой свип: ноты 24…96 с шагом 2, таблицы 0/3/6,
warp/fold 1.0 — худшие значения совпали до 0.1 дБ.

### 2.2 WDF-сатурация (`src/instrument/fx_wdf.h`)

* полифазная свёртка с симметрией ядра: 4 фазы интерполятора считаются за один
  проход, из `4·P+1` коэффициентов умножается половина;
* коэффициенты тона и компенсация усиления кэшируются в `setDrive`/`setTone`,
  а не считаются `pow`/`exp`/`sqrt` каждый сэмпл;
* длина фильтра выбирается шаблоном `WdfClipperT<Taps, FcMilli, BetaX10>`,
  таблица вариантов — в комментарии файла.

Стоимость 4.2 → **3.0 %** ядра; негармоническая доля при 5 кГц и drive 1.0
осталась **−59.0 дБ** (как и было, фильтр не менялся).

### 2.3 Голос (`src/instrument/voice.h`, `src/core/svf.h`)

* `EngineParams` собирались **на каждый сэмпл** для каждого слота: структура +
  три `clamp`. Движки читают параметры в `prepare()`, `render()` их не трогает,
  поэтому теперь параметры кэшируются на блоке управления (128 сэмплов).
* `Svf::process` каждый сэмпл делил на `drive`; `1/drive + 0.25` теперь считается
  в `setParams`. Для 16 голосов × 8 слотов это 128 делений на сэмпл.

### 2.4 Мелочи в сэмпловых циклах

* `Dynamics` (компрессор): `20·log10` и `pow(10, db/20)` заменены на
  `fastLog2`/`fastExp2` (ошибка 0.001 дБ, шесть умножений вместо libm).
* `Resynth`: `pow(freq/1000, tilt)` считался 32 раза за сэмпл — теперь
  коэффициент на партиал обновляется раз в 16 сэмплов.
* `Granular`: окно Ханна через `std::cos` на каждое зерно каждый сэмпл —
  заменено табличным косинусом (1024 точки, ошибка < 3·10⁻⁶); `1/sqrt(overlap)`
  пересчитывается раз в 16 сэмплов.

## 3б. Стоимость Robin и Arp (25.10.2026)

Замер на одном и том же патче (8 нот, 3 слота, 5 с аудио, 2 прогона):

| конфигурация | RMS | CPU |
|---|---|---|
| robin 0, arp 0 | 0.3607 | 50.1 / 51.9 % |
| robin 1 (+12), arp 0 | 0.3476 | 52.9 / 52.4 % |
| robin 1, arp 1 | 0.3476 | 52.9 / 52.8 % |

**Robin добавляет 2.3…3.5 % ядра** (сходится с отдельным замером 2.3–2.9 % на
стерео-поток: STFT 1024 с шагом 256, два канала, 187 кадров в секунду).
**Arp стоит ноль**: он не обрабатывает звук, а планирует ноты — разница в
пределах разброса стенда (±5 % между прогонами на этой машине).

Найдено по ходу: WDF-модель драйва оверсэмплировалась дважды — внутри
`WdfClipper` (4x) и внешним `Fir4x` (`oversample=true` в профиле) — это давало
**14.50 %** ядра на один драйв и **17.36 %** на всю цепочку. После того как
профиль WDF объявлен без внешнего оверсэмплинга: 3.35 % и 5.71 % при том же
алиасинге. Материальные резонаторы дешевле, чем ожидалось (24 моды — 0.40 %),
дорогим остаётся только оверсэмплированный драйв.

Три вещи, найденные при переносе COMB и хоруса:

1. **16x-оверсэмплинг ParallelComb стоит 12.47 % ядра** — в 25 раз дороже
   самого алгоритма без него. По умолчанию выключен (`combOversample = false`);
   включать только если нужен именно алиасинг-фри характер на высоких нотах.
2. **Прошивочный хорус дороже нашего простого в 16 раз** (2.04 % против 0.13 %):
   24-битная целочисленная программа плюс 64-отводная sinc-конверсия на входе и
   выходе при 48 кГц. Поэтому он не дефолт: `chorusModel = 0` — простой хорус,
   `1` — прошивочный (там же своя «фирменная» модуляция).
3. **`-w` для сторонних `.cpp`.** `ChorusCore.cpp` — машинно-сгенерированный код
   с одним неиспользуемым массивом; править его нельзя (копия без изменений),
   поэтому он собирается отдельной единицей трансляции с `-w`, а не глушением
   предупреждений по всему проекту.

## 4. Что проверяли и отвергли

| вариант | почему нет |
|---|---|
| финальная ступень среза 0.25 (полуполосная, самая дешёвая) | алиасинг нелинейностей рушится с −74 до **−32 дБ**: зеркала упираются в 24 кГц |
| `decimC` на 81 и 65 отсчётов при срезе 0.22 | алиасинг тот же, а выигрыш уже в пределах разброса замера — не стоит усложнения |
| `fastSin` для дрейфа Organics | поднял шумовой пол: алиасинг −58.5 → −54.9 дБ (порог стенда −55) — вернули точный `sin` |
| `fastSin` для дрейфа Resynth | уводит фазы партиалов (накапливается секундами): спектр тот же, но копия декореллирует — вернули точный `sin` |
| WDF с 81 отсчётом при срезе 0.125 | −30 дБ алиасинга вместо −59; срез 0.125 вплотную к Найквисту не годится |
| та же FIR на 129 отсчётов (срез 0.118) | −52 дБ, 2.67 % ядра: экономия 11 % ценой 7 дБ алиасинга — оставлено как опция в шаблоне, по умолчанию не включено |
| оверсэмплинг WDF 2x вместо 4x | не проверялось до конца: конструкция `chowdsp_wdf` считает схему на частоте потока, а 2x сузит запас по зеркалам; выигрыш ожидается ~30 % от 3 % — не приоритет |

## 5. Что даст следующий шаг

1. **Granular — самый дорогой движок** (2.48 % на голос, 41 % на 8 голосов).
   Внутри: полифазный sinc на 32 отвода **на каждое зерно на каждый сэмпл**.
   Замена на 16 отводов с двойным окном даст ×2 при просадке образов примерно
   с −80 до −62 дБ (нужно мерить стендом, там порог −55 дБ).
2. **Harmonic**: 0.92 % на голос при 64 партиалах — таблица MIP уже есть,
   дальше только SIMD по партиалам.
3. Качество WDF (Eco/Normal/High) как переключатель `WdfClipperT<...>` —
   шаблон уже параметризован, нужен только выбор по настройке.
4. FX живёт один инстанс на плагин, поэтому 7.7 % ядра — это цена «за всё»
   (с COMB и прошивочным хорусом). Дальше резать: общий оверсэмплер на
   Drive + WDF вместо двух (сейчас 4x + 4x внутри), и 2x для Fuzz. Прошивочный
   хорус при желании заменяется на 32-отводную конверсию — это ~0.6 % экономии
   ценой −20 дБ подавления зеркал.
5. Spectre — единственный эффект с задержкой (окно 512·2^index, при index=2 это
   2048 отсчётов ≈ 43 мс). При `mix = 0` он не считается и задержки не даёт;
   в остальных случаях нужно либо компенсировать задержку в хосте, либо держать
   окно ≤ 1024.
