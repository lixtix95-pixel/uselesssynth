# OROGEN — рабочее пространство

Синтезатор по мотивам Terrain (9 движков, 16 фильтров, 16 эффектов, 8 слотов A–H),
DSP-ядро на C++ без зависимостей + обёртка VST3 на JUCE 8.

## Как выбрать движок и источник

Нажмите карточку слота **A–H**, выберите тип в **ENGINE**, затем таблицу,
сэмпл, материал или луп в **SOURCE**. Для FM/Harmonic источник не нужен и
список отключён. В CHOP доступны три лупа; прежние сохранённые значения 3–7
не переписываются и звучат как последний луп. Свои файлы через этот список
пока не импортируются. Подробные параметры — в PARAMS.

Wavetable исправлен по результатам ASan и спектральных/переходных тестов.
Параметры старых проектов сохранены, но исправления намеренно меняют звук в
отдельных случаях: в частности, **Tilt ниже 0.3 теперь действительно затемняет**,
а очень высокие ноты и переключения таблицы/оверсэмплинга обрабатываются иначе.
Проверки и ограничения: `orogen-dsp/ENGINE-01-wavetable.md`.

Финальные прогоны: DSP **25 наборов, 535 OK, 0 FAIL**; полный
native/X11/XTEST плагина **258/258**. ASan/UBSan/LSan:
**2430** крайних сочетаний Wavetable, 0 NaN/Inf. Реальные XTEST-клики в SOURCE:
**48/48**; выбор источника в GUI изменил удержанную ноту в AudioProcessor
(ΔRMS **0.028581**). Выбор из hosted VST3 передал хосту begin/value/end;
256 аудиоблоков с автоматизацией таблицы/Warp/Fold дали **0** выделений
памяти в измеряемом аудиопотоке и 0 NaN/Inf. Это конкретные стенды, не
испытание в рабочей DAW.

## FX RACK: добавление и порядок

На главном экране нажмите **FX RACK** или **X**. В списке слева сигнал идёт
сверху вниз. Выберите тип в выпадающем списке и нажмите **+ ADD**; выберите
строку, чтобы настроить её справа. **UP / DOWN** переставляют выделенную
строку в аудиотракте, **REMOVE** убирает её, **ON/OFF** отключает обработку,
не стирая ручки. Перетаскивание строк мышью не реализовано. **SYNTH** возвращает
основной экран; **ALL PARAMETERS** открывает полный оверлей.

В INIT показаны 13 прежних стадий, все выключены. Можно удалить ненужные строки;
в цепи не более **16 экземпляров**, одного типа — не более **4**. Новая копия
начинает с настроек экземпляра #1, после чего её ручки, ON/OFF, DSP-состояние
и параметры автоматизации независимы. Чипы на главном экране управляют #1;
если #1 удалён, чип показывает ADD и возвращает его в цепь при наличии места.
Порядок и все значения экземпляров сохраняются в DAW state, JSON-пресете и банке.

Прежние **376** ID и диапазоны не изменены; новые параметры копий и позиции
добавлены после них. Старые состояния без позиций восстанавливают исходный
порядок; более старые без переключателей — прежний тракт с ON. При изменении
состава/порядка звук ненадолго затухает и появляется снова (переход 6+6 мс).
Удалённые/выключенные узлы могут сохранять внутреннюю историю и возобновлять
её при повторном добавлении/включении; Delay при OFF продолжает отсчитывать
историю. Подготовка новых экземпляров идёт вне аудиоколбэка; до готовности
дополнительный эффект может кратко отсутствовать в тракте.

Базовая сухая задержка ROBIN **1024 отсчёта** сохраняется даже после удаления
#1; каждая добавленная копия ROBIN вносит ещё 1024, включая OFF. Включённые
Spectre/прошивочный Chorus могут добавить задержку; она сообщается хосту, но
поведение автоматической компенсации при её изменении зависит от DAW.
DC-блокер и защитный лимитер активны всегда. В исходном порядке старых стадий
используется прежний аудиотракт; в пользовательском порядке лимитер находится
в конце цепи. См. `orogen-dsp/FX.md`.

FX-дополнение сверено с предоставленным пользователем MonoHuice 0.9.15:
в GLITCH добавлены DIST, независимые DRY/WET, OFFSET/XFADE, синхронизация с
BPM хоста, фильтр и управление повторами; в SPECTRE — REJECT/ATTACK/RELEASE
и расширенные диапазоны; в COMB — ODIN MIX и расширенные диапазоны. Значение
**FOLLOW** означает, что действует прежняя ручка; при вводе нового значения
расширенная ручка её перекрывает. Новых FX-LFO или секвенсора нет.
CHORUS firmware показывает восемь значений 0–127 и имеет режимы Legacy/V1/V2.
Новый INIT выбирает V2 и правильную частоту GLITCH; старые состояния — Legacy.

включая ASan/UBSan; перестановка EQ/Drive дала ΔRMS **0.431009470**, изменение

передаётся с рабочего потока; отдельный сценарий передачи прошёл TSan
(102400 кадров), это не TSan всего плагина.

В Granular исправлены асимметрия оценки краёв зерна и неполная последняя
ячейка огибающей. Для конкретной атаки MIDI 45 / Position 0 пик Choir
**1.364268 → 0.919871**, Vox **1.306653 → 0.881589**; изменился и RMS.
Это исправление оценок зерна без изменения общего уровня/лимитера, но не
гарантия headroom: в другом сценарии Choir по-прежнему **1.260694**.
Случайные Pitch/Position Spread теперь независимы для нот и слотов: два
стереослоя при Spread 0.6/Reverse 0 дали корреляцию **1.000000 → −0.034293**.
При ненулевом Spread сохранённые проекты могут зазвучать иначе; при Spread 0
сохранён прежний базовый поток. Дисплей, FX-чипы, узлы модуляции, ADSR,
LFO и VectorPad передают хосту сбалансированные жесты автоматизации.

Нажатие ON/LEVEL/TUNE карточки теперь выбирает свой слот: проверка peer
**0/24 → 24/24** при 1280×800, в сумме **72/72** на трёх размерах окна.
Проверка селектора усилена: XTEST-клики по меню переключают **9 типов × 8
слотов = 72/72**, а аудио девяти движков различается во всех **36/36** парах.
В двух ограниченных сценариях текущего Choir через хост пики **0.348848 /
0.808359**, 0/96000 отсчётов достигают 0.98; другие патчи этим не гарантируются.
Granular использует отдельные
воспроизводимые потоки Reverse для разных нот и слотов: два идентичных слоя
при 50% дают ΔRMS/RMS **0 → 0.991847** в Voice и **0.993401** в VST3-хосте.
На 0/100% контрольные рендеры до/после той прежней правки направлений
побайтно совпали; позднее исправление Spread меняет ненулевой Spread и при
этих крайних значениях Reverse.

Метры слотов получают пики окнами 10 мс и затухают; до исправления TSan
обнаруживал гонку с GUI, после — нет в проверенном сценарии. При остановленном
аудиоколбэке GUI гасит старый уровень через 250 мс. Нативный repaint метра:
**1 024 000 → 400 пикселей** на вызов; оставшиеся следы — 0 пикселей.
Макет 1280×800 сохранён; на предыдущем этапе были доступны **376/376** параметров;
подписи PARAMS ранее увеличены 7 → 10 px; статус показывает Grain Reverse.
Сохранены все 298 прежних ID и их порядок, 8 новых добавлены в конец.
Пользовательская загрузка аудиофайлов в GUI не реализована. Из распакованного
source ZIP повторно прошли **411/411** DSP-проверок; оба архива прошли CRC,

Совместимость: звук старых проектов может измениться из-за Granular/MIP/Organics,
исправления Pan/Level и лимитера при перегрузе; Delay Feedback выше 0.92 и Plate
pre-delay выше 100 мс теперь используют сохранённые значения вместо прежних
ошибочных пределов. Исправления нормировки и точности высоты Granular и
поведения Delay при автоматизации Mix/Time также могут изменить звук прежних
проектов. Detune и Pitch фиксируются для каждого зерна при его запуске: на удержанной ноте
автоматизация действует на последующие зёрна. При Reverse между 0 и 1 ранее
сохранённые патчи могут звучать иначе из-за независимых потоков направления.

Проверка DSP с сохранением кодов выхода (`make test` теперь также
останавливается на первом неуспешном тесте):

```bash
cd orogen-dsp
make -j1 all
make test             # запускать отдельно от сборки ради честного CPU-теста

make asan-delay       # отдельный стенд безопасности Delay
```

Сборка плагина на **Windows / Visual Studio 2022** — распаковать
`OROGEN-vst3-vs2022.zip` и запустить `build_vst3.bat` (JUCE скачается сам).

Сборка плагина в Linux-песочнице (нужны системные dev-пакеты X11/ALSA и `cmake`+`ninja`):

```bash
sudo apt-get install -y cmake ninja-build git pkg-config libx11-dev libxrandr-dev \
     libxinerama-dev libxcursor-dev libxext-dev libfreetype-dev libfontconfig1-dev \
     libasound2-dev libcurl4-openssl-dev xvfb openbox

# конфигурация: juceaide собирается на этапе configure и на 2 ГБ RAM без свопа
# падает по OOM — нужен swap и последовательная сборка
CMAKE_BUILD_PARALLEL_LEVEL=1 cmake -S orogen-plugin -B orogen-plugin/build-cmake \
      -G Ninja -DCMAKE_BUILD_TYPE=Release -DOROGEN_BUILD_VST3=ON
CMAKE_BUILD_PARALLEL_LEVEL=1 ninja -C orogen-plugin/build-cmake -j1 \
      OROGEN_VST3 render_ui test_plugin verify_vst3

# Полный тест с настоящим X11-окном требует Xvfb и window manager, например openbox:
xvfb-run -a sh -c 'openbox >/dev/null 2>&1 & wm=$!; sleep 1; \
    OROGEN_GUI_NATIVE=1 ./orogen-plugin/build-cmake/test_plugin; rc=$?; \
    kill "$wm" 2>/dev/null; exit "$rc"'

# Внешний VST3-хост и кадр UI:
xvfb-run -a ./orogen-plugin/build-cmake/verify_vst3 \
    "$(realpath orogen-plugin/build-cmake/OROGEN_artefacts/Release/VST3/OROGEN.vst3)" 1
xvfb-run -a ./orogen-plugin/build-cmake/render_ui \
    "$(pwd)/orogen-plugin/docs/ui_main.png" 0 1280 800
```

Без swap `cc1plus` при сборке `juceaide` убивается OOM (проверено: конфигурация
падала с `fatal error: Killed signal terminated program cc1plus`).
