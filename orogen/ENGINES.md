# Движки синтеза: разбор по одному и как их строить

Документ к демке **OROGEN** (`orogen/index.html`) — техническое углубление в 8 движков Terrain.
Всё, что касается внутренностей Terrain, — реконструкция по описанию параметров на официальной странице и видео-мануалу (помечено `(вывод)`). Всё, что касается алгоритмов и кода, — проверено в демке.

---

## 0. Контракт движка: как 8 разных генераторов живут в одном голосе

Прежде чем разбирать каждый движок отдельно — общая рамка. Terrain: «8 осцилляторов A–H, у каждого 8 движков».
Значит, движок — это не отдельный класс синтезатора, а **полиморфный юнит внутри голоса**, с одинаковым интерфейсом:

```cpp
struct EngineBase {
    virtual ~EngineBase() = default;
    // вызывается при note-on: сброс фаз, возбуждение мод, старт гранул
    virtual void start (int midiNote, float velocity, float sampleRate) = 0;
    // вызывается раз в блок (не на каждый сэмпл!): тяжёлые расчёты коэффициентов
    virtual void prepare (const EngineParams& p, float sampleRate, int numSamples) = 0;
    // горячий цикл: ровно один сэмпл
    virtual float render (const EngineParams& p) = 0;
    virtual bool  isFinished() const { return false; }
};
```

Три правила, которые определяют всю производительность:

1. **Тяжёлое — в `prepare()`, не в `render()`.** Интерполяция кадров вейвтейбла, коэффициенты резонаторов, перевод Гц в инкременты фаз, расчёт длин грейнов — всё считается на блок (32–512 сэмплов). В `render()` не должно быть ни делений, ни `pow`, ни `exp`, ни `std::vector::push_back`.
2. **Никаких аллокаций в аудио-потоке.** Все буферы (грейны, моды, партиалы) — фиксированного размера, аллоцируются при `prepareToPlay`.
3. **Голос = 8 движков параллельно**, они **суммируются до фильтра**: один фильтр на голос, не на слот. Это и дешевле, и звучит «как один инструмент», а не как 8 инструментов.

Схема голоса:

```
MIDI note ──► Voice
               ├── slot A: Wavetable  ─┐
               ├── slot B: Granular   ─┤
               ├── slot C: FM         ─┤   Σ  ──► SVF-фильтр ──► amp env ──► pan/level ──► шина
               ├── …                   │
               └── slot H: Organics   ─┘
             (Robin-карточка может маскировать слоты: играет не всё сразу)
```

В демке это буквально `for (si = 0..7)`, а `v.mask` (битовая маска) реализует Robin.

## 1. Wavetable — «рабочая лошадка»

**Суть.** Один цикл волны хранится как таблица, читается по фазе 0…1. Много кадров = морфинг по позиции.

**Параметры Terrain:** WT Pos, Warp, Fold (+ на «задней панели» — FM/phase distortion по таблице).
**Параметры демки:** `WT Pos` (кадр), `Warp` (сатурация), `Fold` (волновая складка), `Detune`.

**Алгоритм демки** (двумерная интерполяция: по фазе и по кадрам):

```cpp
float read (float phase, float pos) {
    float fp = pos * (frames-1);
    int   i0 = (int)fp;  float ff = fp - i0;
    int   i1 = std::min(frames-1, i0+1);
    float x  = phase * TABLE_N;  int xi = (int)x;  float xf = x - xi;
    int   xa = xi & (TABLE_N-1), xb = (xa+1) & (TABLE_N-1);
    float a = lerp(tbl[i0][xa], tbl[i0][xb], xf);
    float b = lerp(tbl[i1][xa], tbl[i1][xb], xf);
    return lerp(a, b, ff);
}
```

**Главная проблема — алиасинг.** Таблица из 2048 сэмплов содержит, по Найквисту, до 1024 партиалов. Если играть ноту C5 (523 Гц), то при 44.1 кГц без фильтрации всё выше 22 кГц отразится вниз и зазвенит «металлом». Решение — **MIP-таблицы по октавам**:

```cpp
// при загрузке каждой таблицы строим N уровней, каждый = предыдущий, отфильтрованный и децимированный ×2
for (int lvl = 1; lvl < LEVELS; ++lvl)
    decimateHalfBand (mips[lvl-1], mips[lvl]);   // FIR полуполосный, ×2 децимация

// в рендере — выбор уровня по частоте ноты, а не по громкости:
int level = clamp (int(std::log2 (freq / baseFreq)), 0, LEVELS-1);
```
Практика (Vital, Serum): 11–13 уровней, `baseFreq ≈ 20 Гц`, кроссфейд между уровнями ±полутона, чтобы не «щёлкало» при переходах. Плюс `2×` оверсэмплинг на выходе, если включён Warp/Fold — они нелинейные и сами генерят гармоники выше Найквиста.

**Warp** (в демке — `ufb`, быстрый tanh):
```cpp
float ufb (float x) {              // рациональное приближение tanh, без библиотечных вызовов
    if (x < -3) return -1; if (x > 3) return 1;
    float x2 = x*x;  return x * (27 + x2) / (27 + 9*x2);
}
s = ufb (s * (1 + warp*6));        // 0 → прозрачно, 1 → жёсткое ограничение
```
**Fold** — «волновая складка» (wavefolding): сигнал отражается при превышении ±1, что даёт характерный «скрежет» и субгармоники:
```cpp
s = std::sin (s * (1 + fold*6) * HALF_PI);   // дешёвая замена треугольной складки
```

**Чего нет в демке, но обязательно в плагине:** MIP-уровни, оверсэмплинг нелинейностей, кроссфейд уровней, и — «рисование» собственной таблицы (Terrain: «draw your own movement on top»), т.е. редактор кадров + FFT-конверсия из WAV.

**Цифры демки:** 8 таблиц × 6 кадров × 2048 сэмплов ≈ 393 КБ float32; чтение — 2 интерполяции на сэмпл, ~5 нс. Самая дешёвая из «богатых» движков.
**Сложность реализации: 2/5.** Самое сложное — не чтение, а генератор контента и MIP-иерархия.

## 2. Sample — «плёнка, которую играют как инструмент»

**Суть.** Прямое воспроизведение записи с питч-шифтом по нотам. Terrain: 2 177 one-shot'ов, loop-регион, fade-in, Scan, Air.

**Параметры демки:** `Scan` (позиция чтения), `Grain` (дробление на куски — «заикание»), `Tone`, `Air`.

**Алгоритм:**
```cpp
float render() {
    pos += rate;                       // rate = 2^((note-60)/12) * (sampleRate_orig / sampleRate_host)
    if (pos >= loopEnd) pos = loopStart + (pos - loopEnd);
    int i = (int)pos;  float f = pos - i;
    return buf[i] + (buf[i+1] - buf[i]) * f;    // линейная интерполяция
}
```

**Три ловушки, каждая слышна:**

1. **Интерполяция.** Линейной достаточно при понижении и близких к оригиналу нотах; при повышении на октаву+ слышен «цифровой песок» по верхам. В продакшене — 4-точечная Эрмитова (Catmull-Rom):
```cpp
float hermite (float xm1, float x0, float x1, float x2, float t) {
    float c = (x1 - xm1) * 0.5f, v = x0 - x1, w = c + v, a = w + v + (x2 - x0) * 0.5f, b = w + a;
    return ((a*t - b)*t + c)*t + x0;
}
```
2. **Ресемплинг при повышении = алиасинг.** Для нот выше оригинала нужен MIP-набор сэмпла (как у вейвтейбла) либо sinc/BSpline-интерполятор с огибающей окна.
3. **Питч без изменения длины / длина без изменения питча** — если нужно, это уже time-stretch (WSOLA/Phase Vocoder), отдельная подсистема.

**Scan** (позиция) — это не просто «начало воспроизведения»: в Terrain, судя по скриншотам, у сэмпла есть loop-регион в середине, а Scan двигает точку чтения — фактически «скраб» по записи. В демке Scan управляет стартовой позицией гранулярного чтения, поэтому звучит как «проигрывание с середины».

**Цифры:** в демке 8 синтезированных «источников» по 1.6 с (≈70 тыс. сэмплов каждый). Реальные 2 177 one-shot'ов — это ~3 ГБ: их нельзя держать в RAM целиком, нужен **стриминг с диска** (`mmap` + префетч первых N килобайт каждого файла в кэш, чтобы атака не опаздывала).
**Сложность: 2/5** для простого плеера, **4/5** для стриминга + MIP + лупов без щелчков.

## 3. Granular — «облако из осколков»

**Суть.** Запись не играется целиком, а «нарезается» на короткие осколки (2–200 мс), которые запускаются с разными позициями, перекрываются и складываются в плотное облако.

**Параметры Terrain:** Size, Density, Spray, Position (+ Freeze).
**Параметры демки:** `Position`, `Size`, `Density`, `Spray` — по 2 грейна на слот.

**Алгоритм (демка, упрощённый real-time планировщик):**
```cpp
for (int g = 0; g < GRAINS_PER_SLOT; ++g) {      // 2 в демке, 16–64 в продакшене
    grain.age++;
    if (grain.age >= grain.len) {                // перезапуск грейна
        grain.age  = 0;
        grain.len  = sizeSec * sampleRate * (0.6f + randf()*0.8f);
        grain.pos  = (position + (randf()-0.5f)*spray) * bufLen;   // позиция с разбросом
    }
    float w = window (grain.age / grain.len);     // Hann
    out += buf[(int)grain.pos] * w;               // чтение с питч-сдвигом
    grain.pos += rate;
}
```

**Окно — это и есть тембр.** Hann (в демке) — гладкое, «облачное»; Tukey/прямоугольное с короткими скатами — «зёрнистое» с щелчками; окно Гаусса — плотное, «стеклянное». Формула Hann без cos: `w = 0.5 - 0.5*cos(2π·a)`, но в горячем цикле лучше табличный поиск в 1024 точки (в демке — `WINTAB`).

**Три параметра, которые всё определяют:**
| Параметр | Что делает физически | Крайние значения |
|---|---|---|
| Size | длина грейна → «зернистость» ↔ «размытость» | 5 мс = щелчки и «искры», 200 мс = почти обычный сэмпл с фленжем |
| Density | грейнов в секунду → перекрытие | мало = разрозненные капли + паузы, много = сплошной дрон |
| Spray | случайный разброс позиции | 0 = «замороженный» тон, 1 = хаос из разных мест записи |

**Freeze** — это не «стоп», а переключение источника: позиции грейнов не двигаются вперёд, но сами грейны продолжают генерироваться с тех же мест. Дешёвая и очень характерная штука.

**Главные подводные камни:**
- **Плотность ≠ громкость.** При увеличении Density простое суммирование даёт клиппинг. Нужна нормализация `1/sqrt(activeGrains)` или мягкий лимитер — иначе крайние положения ручки будут в 3 раза громче средних.
- **Пропуск грейнов при низкой плотности.** Если плотность мала, грейны идут редко, но каждый полный — иначе получится AM-модуляция вместо «капель».
- **Гребёнка.** Два грейна с одинаковой позицией и питчем дают не «плотнее», а «фленжер». Поэтому Spray — не украшение, а необходимость.
- **CPU.** 14 голосов × 8 слотов × 32 грейна = 3584 окна на сэмпл — это уже серьёзно. Продакшн-решение: **общий пул грейнов** на всю полифонию (один планировщик, общий лимит 512 грейнов), а не по пулу на голос.

**Цифры демки:** 16 грейнов максимум (8 слотов × 2), rms 0.095, 6% CPU от общего бюджета. В плагине: 24–48 грейнов на слот, пул на весь инструмент.
**Сложность: 3/5** (планировщик простой, сложность — в нормализации и пулах).

## 4. FM — «форма волны, которую гнёт другая волна»

**Суть.** Частотная модуляция: фаза несущей сдвигается выходом модулятора. Мгновенно даёт богатые, «звонкие» и «металлические» спектры из двух синусов.

**Параметры Terrain:** Ratio 1, FM 1, Ratio 2, FM 2, Feedback, алгоритмы (Split и др.) — то есть 2 оператора + обратная связь в духе DX7.
**Параметры демки:** `Ratio`, `FM 1`, `FM 2`, `Feedback` — 2 оператора + второй модулятор на 1.5× частоты.

**Алгоритм:**
```cpp
// классическое 2-операторное FM с обратной связью
ph1 += inc;                  // несущая
ph2 += inc * ratio;          // модулятор
float mod = std::sin(TAU * ph2) * index;    // index = FM amount * maxIndex
float s   = std::sin(TAU * ph1 + mod);
// feedback: оператор модулирует сам себя по предыдущему выходу
s = s*(1-fb) + ufb(s*3)*fb;
```

**Ключевая формула — индекс модуляции и ширина спектра.** Число значимых боковых полос ≈ `index + 1` (правило Карсона: `BW ≈ 2(Δf + fm)`). Отсюда: чтобы «звон» был управляемым, индекс должен быть **в единицах радиан фазы**, а не «0…100»:

```cpp
index = fmAmount * 8.0f;     // 0 → чистый синус, 8 → ~9 пар боковых полос
```
Именно поэтому у Terrain на «задней панели» FM живёт отдельно: он требует индекса в радианах и понимания, что `ratio` целочисленный = гармонический спектр, нецелый = **ингармонический** (колокола, металл, «стекло»).

**Почему ratio 3 и 5 дают «FM Tine»:** нечётные целые отношения дают полый, «электрическое пиано» тембр — классика DX7 Rhodes. Чётные (2, 4) — «органнее» и мягче.

**Алиасинг.** FM генерирует бесконечный спектр, и он мгновенно уходит выше Найквиста. Меры:
1. Ограничение индекса по частоте ноты: `maxIndex ≈ (Nyquist/f0 - 1)`.
2. Оверсэмплинг 2×–4× на выходе движка.
3. Для «эталонного» звука — таблицы синуса с `sin(x + mod)` через полиномы или предвычисленная таблица + интерполяция.

**Фишка для «своего» звука:** feedback через `tanh` (как в демке) вместо чистого синуса даёт мягкую «шершавость» и не улетает в хаос, в отличие от чистого DX-фидбэка, который при >0.7 превращается в шум.

**Цифры демки:** rms 0.369, самый громкий движок из 8 (у синуса высокий crest factor, аккуратно с уровнем); CPU низкий — 2 синуса на сэмпл.
**Сложность: 1/5** для 2 операторов, **4/5** для полноценного DX7-алгоритма на 6 операторов с матрицей модуляций.

## 5. Harmonic — «аддитив, таблица партиалов»

**Суть.** Звук как сумма синусов с заданными амплитудами: «таблица партиалов» — это буквально список `[1.0, 0.5, 0.25, …]`. Terrain: таблицы вроде *Glass Harmonics*.

**Параметры демки:** `Tilt` (наклон спектра — яркость), `Spread` (разброс фаз/детюн), `Shape` (позиция по кадрам таблицы), `Motion`.

**Алгоритм демки** — он же, по сути, «движок №7»: чтение таблицы с наклоном.

```cpp
float sample (float phase) {
    float s = 0;
    for (int k = 1; k <= P; ++k)
        s += amp[k-1] * std::sin (TAU * k * phase);
    return s;
}
```
Наивно это `P` вызовов `sin` на сэмпл. Правильно — **рекуррентность Чебышёва** (её использует Resynth в демке):

```cpp
// sin((k+1)φ) = 2·cos(φ)·sin(kφ) − sin((k−1)φ)
float prev = 0.f, cur = sinPhi, acc = 0.f;
for (int k = 1; k <= P; ++k) {
    acc += amp[k-1] * cur;
    float nxt = 2.f * cosPhi * cur - prev;
    prev = cur;  cur = nxt;
}
```
Одно `cos`/`sin` на сэмпл вместо `P` — и получаем 16–64 партиала почти бесплатно. Побочный эффект: рекуррентность численно неустойчива для очень больших `P` (накапливается ошибка) — при P > 128 надо переходить на прямую сумму или на осциллятор-банк с SIMD.

**Tilt** — наклон спектра: `amp[k] *= pow(k, slope)`. Это самое музыкальное из «незвуковых» движений: `slope = −1` — как пила, `slope = +0.5` — «стеклянно-ярко», `−3` — почти синус.

**Почему это отдельный движок, а не «вейвтейбл»:** в вейвтейбле вы морфите между нарисованными формами; здесь вы управляете **самим спектром** (какие партиалы есть и насколько). Это прямой доступ к «обертоновому составу» — то, что делает звук «стеклянным» (только нечётные высокие), «деревянным» (быстрый спад + шум) или «органным» (1, 2, 3, 4, 6, 8).

**Алиасинг:** партиалы выше `Nyquist/f0` надо глушить. В рекуррентности это делается просто ограничением `P` по ноте: `P_max = min(64, floor(0.47*SR / f0))` — как в Resynth демки (`maxPartials`).

**Цифры демки:** rms 0.162, peak 0.54. CPU сопоставим с FM при P=16.
**Сложность: 3/5** (нужен спектральный редактор для контента, иначе движок «нечем крутить»).

## 6. Modal — «физическое тело: удар и резонанс»

**Суть.** Инструмент моделируется как набор резонансных мод: у металлической пластины — свои частоты и времена затухания, у дерева — другие. Возбуждение (удар/шум) подаётся на банк резонаторов.

**Параметры Terrain:** форма тела (Bowl, Glass…), удар.
**Параметры демки:** `Body` (выбор тела), `Strike` (яркость/сила возбуждения), `Damp` (демпфирование), `Ratio` (растяжка негармоничности).

**Алгоритм демки** — 3 моды с индивидуальным распадом:

```cpp
const Body bodies[] = {
  // частотные отношения мод и коэффициент затухания на сэмпл
  {"Glass", {1.f, 2.32f, 4.25f}, {0.9993f, 0.9986f, 0.9975f}},
  {"Bowl",  {1.f, 1.74f, 3.11f}, {0.9996f, 0.9990f, 0.9982f}},
  {"Plate", {1.f, 3.07f, 6.40f}, {0.9990f, 0.9980f, 0.9965f}},
  {"Wood",  {1.f, 2.90f, 5.20f}, {0.9985f, 0.9970f, 0.9950f}}
};

for (int k = 0; k < 3; ++k) {
    ph[k] += inc * ratio[k];
    amp[k] *= decay[k];                 // экспоненциальное затухание
    out += std::sin(TAU * ph[k]) * amp[k];
}
```

**Как проектировать «тела» — формула T60.** Затухание `d` на сэмпл задаёт время до −60 дБ:
```
T60 [сэмплов] = ln(1000) / (−ln d) = 6.9078 / (−ln d)
```
Для тел демки при 44.1 кГц:

| d | T60, сэмплов | T60, мс | Характер |
|---|---|---|---|
| 0.9996 | 17 266 | 391 | «Bowl» — долгий гул |
| 0.9993 | 9 866 | 224 | «Glass» — звонкий колокол |
| 0.9986 | 4 931 | 112 | вторая мода Glass |
| 0.9982 | 3 834 | 87 | третья мода Bowl |
| 0.9975 | 2 760 | 63 | «стеклянный» призвук |

Обратите внимание: **высокие моды затухают быстрее низких** — это и есть подпись «настоящего материала». Если сделать одинаковый распад, звучит как «орган с шумом», а не как предмет.

**Что в реальном модальном синтезе делается сложнее:**
- Моды считаются не «на глаз», а из **физики**: `f_n ∝ (n²)` для балки, `∝ (2n−1)` для струны, для мембраны — из функции Бесселя. Негармоничность задаётся коэффициентом `B`: `f_n = n·f0·sqrt(1 + B·n²)` — так звучат фортепианные струны.
- Возбуждение — не «просто амплитуда», а короткий импульс/шум, пропущенный через фильтр позиции удара (удар ближе к центру = меньше высоких мод).
- Затухание зависит от амплитуды (нелинейное демпфирование) — это даёт «естественный» хвост.
- Полноценно: 20–80 резонаторов на голос, реализуются как **биквады с очень высокой Q** (дешевле, чем `sin`, и моды можно «сдвигать» в реальном времени):

```cpp
// резонатор Кука (Cookbook / constant-Q bandpass)
y[n] = a0*x[n] + a1*y[n-1] + a2*y[n-2];
a0 = (1 - r²)/2,  a1 = 2·r·cos(2π·f/SR),  a2 = −r²;
// r = exp(−π·BW/SR): ширина полосы ↔ время затухания
```

**Подводные камни:** CPU (80 резонаторов × 14 голосов — это уже отдельная битва), «звенящий» пик при высокой Q (нужен headroom), и то, что модальный движок **не звучит без правильного возбуждения** — именно поэтому в демке Organics и Modal такие разные: у одного есть корпус, у другого — удар.

**Цифры демки:** самый тихий (rms 0.058 — типично для ударного звука с большим crest), CPU низкий.
**Сложность: 4/5** (математика простая, звук — нет; нужен инструмент для проектирования тел).

## 7. Resynth — «звук, пересобранный из собственного спектра»

**Суть.** Взять запись, разложить на партиалы + огибающие, а потом **заново синтезировать** — но уже как управляемый инструмент: тянуть ноты, менять яркость, время, питч без артефактов.

**Параметры Terrain:** «пересборка из спектра», источники вроде Vocal 12.
**Параметры демки:** `Spectrum` (кадр анализа), `Tilt` (наклон), `Air` (шумовой остаток), `Detune`.

**Как это работает (в демке — по-настоящему, с анализом):**

1. **Анализ (офлайн, один раз при загрузке).** Для каждого кадра записи считаем амплитуды первых 16 партиалов от f0 = 110 Гц. В демке — честный ДПФ на частотах партиалов через рекуррентный поворот фазы:
```js
for (let k = 1; k <= P; k++) {
  let re = 0, im = 0, c = 1, sn = 0;
  const w = TAU * f0 * k / sr, cw = Math.cos(w), sw = Math.sin(w);
  for (let i = 0; i < win; i++) {                 // win = 2048, окно Hann
    const x = buf[start + i] * hann[i];
    re += x * c; im += x * sn;
    const nc = c*cw - sn*sw; sn = sn*cw + c*sw; c = nc;   // поворот фазора
  }
  amps[k-1] = 2 * Math.hypot(re, im) / win;
}
```
Это дешевле полного FFT, когда нужно всего 16 бинов — и точнее по частоте (не привязано к сетке FFT).

2. **Ресинтез (в реальном времени).** Осциллятор-банк по партиалам, но вместо `P` синусов — **рекуррентность Чебышёва** (1 триг. функция на сэмпл):
```cpp
float resynth() {
    float sn = sinP * c + cosP * s;      // поворот фазора основного тона на inc
    float cs = cosP * c - sinP * s;      // (c,s) — текущая фаза f0
    float prev = 0, cur = sn, acc = amps[0]*cur;
    for (int k = 2; k <= maxK; ++k) {
        float nxt = 2*cs*cur - prev;     // sin(kφ) из sin((k−1)φ) и sin((k−2)φ)
        prev = cur; cur = nxt;
        acc += amps[k-1] * cur;
    }
    return acc;
}
```
3. **Шумовой остаток (Air).** Разница между оригиналом и суммой партиалов — это шум/дыхание/воздух. В демке — `Air` просто подмешивает шум. В продакшене остаток вычисляют при анализе (оригинал − ресинтез) и хранят как **спектральную огибающую шума** (band-limited noise, чтобы не «шипело» на верхах).

4. **Огибающие партиалов.** В демке «кадры» анализа — это и есть огибающие (6 кадров = 6 моментов). В продакшене — экспоненциальные огибающие на партиал (атака/спад), чтобы ресинтез дышал, а не «сэмплировал» кадры.

**Что это даёт на практике:** вокал, струнные и «живые» источники, которые можно **играть** как синтезатор: тянуть длинные ноты, менять яркость, не теряя «человечности». Это самый «магический» из движков — и самый требовательный к корректности анализа.

**Подводные камни:**
- **Непостоянный f0** (вокал, вибрато): нужен pitch-tracking, иначе партиалы «плывут». Terrain, судя по названию («Vocal 12»), работает именно с вокалом — там это критично.
- **Фазовая некогерентность:** если не следить за начальными фазами партиалов, атака теряет «щелчок». Лечится детерминированными фазами и переходом на прямую сумму в момент атаки.
- **Партиалы выше Найквиста:** `maxK = min(16, 0.47·SR/f0)` — обязателен (в демке `maxPartials`).
- **Численная устойчивость** рекуррентности: при P>64 накапливается ошибка → периодически пересинхронизировать `(c,s)` из точной фазы.

**Цифры демки:** rms 0.16 при C4, 0.21 при C7 (ограничение партиалов сработало), инициализация всех таблиц + анализ — ~100 мс (JS, одноразово).
**Сложность: 4/5**, из них 3 балла — это анализ/подготовка контента, а не реалтайм.

## 8. Organics — «мультисэмпл с живым телом»

**Суть.** Гибрид: запись играется как сэмпл, но у неё есть **корпусный резонатор** (тело) и характерный транзиент (удар, щипок, дыхание). Так «пиано» становится «пиано из другого мира», а «струнные» — «струнными, которые гнутся».

**Параметры Terrain:** 74 инструмента (pianos, plucks, strings), «ready to be bent out of shape».
**Параметры демки:** `Body` (частота корпуса), `Strike` (транзиент/шум), `Tone` (ФНЧ), `Drift` (микрорасстройка).

**Алгоритм демки** — три слоя в одном сэмпле:

```cpp
float organics() {
    // 1) зоны мультисэмпла (низ/середина/верх)
    const auto& buf = sources[table + zone(note)];

    // 2) чтение с питч-шифтом и «дрейфом» (микрорасстройка, как живой инструмент)
    pos += orgRate * tune * drift;   if (pos >= len) pos -= len;
    float x = lerp(buf[(int)pos], buf[(int)pos+1], frac(pos));

    // 3) корпус — 2-полюсный резонатор на «телесной» частоте
    float y = bz1*a1 + bz2*a2 + x*b0;    // 90 Гц · 2^(body·3.8), r ≈ 0.9972
    bz2 = bz1;  bz1 = y;

    // 4) тембр — однополюсный ФНЧ + транзиент (шум с быстрым спадом)
    tz += (x - tz) * tone;
    return (tz*(1-bodyMix) + y*bodyMix)*0.9 + noise*strike*0.09*transientEnv;
}
```

**Почему это отдельный движок, а не «сэмпл с фильтром»:** потому что (а) **зоны** — разные сэмплы на разные диапазоны нот, чтобы избежать питч-шифта на октаву; (б) **корпус** — это физическая модель, а не EQ: она резонирует на реальной частоте тела и даёт «объём»; (в) **транзиент** привязан к атаке и не тянется вместе с нотой.

**Хитрость с зонами:** в демке зона выбирается по ноте (`<52`, `>72`), и сэмпл сдвигается максимум на ±6 полутонов — это ровно то, что делает качественный мультисэмпл: держать питч-шифт в пределах, где интерполяция не портит тембр. У Terrain 74 инструмента — это, скорее всего, 3–6 зон × 2–3 velocity-слоя на инструмент.

**Velocity-слои** — то, чего в демке нет, а в реальном Organics есть: тихая нота звучит не «тише громкой», а **другим сэмплом** (мягкая атака, меньше шума, меньше высоких). Без этого «piano» звучит как «орган с фильтром».

**Drift** — маленькая, но важная деталь: расстройка на ±3 % и случайная на голос. Именно она отличает «живой ансамбль» от «пластикового пресета». В демке `v.orgDrift[si] = 1 + (spread−0.5)·0.03·rand`.

**Цифры демки:** rms 0.283 (второй по громкости после FM), CPU ~ сравним с сэмплом.
**Сложность: 3/5** для реализации, **5/5** для контента (мультисэмплинг с велосити-слоями — это недели записи).

**Главный вывод по громкости:** разброс rms между движками — **в 6 раз** (0.058 у Modal против 0.369 у FM). Это не косметика: в плагине обязательна **калибровка уровня на движок** (per-engine gain trim, компенсирующий crest factor), иначе переключение движка в слоте скачет по громкости на 15 дБ и пользователь decides, что плагин «глючит».

## 10. Что превращает «8 движков» в «инструмент» (то, чего нет в демке)

1. **Единая калибровка:** `engineTrim[8]` — выравнивание rms/crest, чтобы Layer Cake из 3 движков не взрывался.
2. **Умное выключение:** неактивный слот (level=0 или маска Robin) должен полностью пропускаться в цикле — иначе 8 слотов × 14 голосов всегда дают полную нагрузку.
3. **Voice stealing по `engine-cost`:** если слот Modal с 40 модами, у него должен быть приоритет на «кражу», иначе треск.
4. **Denormals:** экспоненциальные затухания (моды, грейны, env) уходят в субнормали и роняют CPU в 10 раз. Стандарт: `x += 1e-20f` в конце, или `_mm_setcsr(_MM_FLUSH_ZERO_ON)`.
5. **Zipper noise:** все ручки, которые меняются на блок, должны сглаживаться (`SmoothedValue`, 5–20 мс) — особенно Cutoff, WT Pos, Position грануляра.
6. **Усреднение по полифонии:** тяжёлые движки (Modal, Granular) — ограничение числа одновременных голосов именно для них.
7. **SIMD:** 4 голоса в одном SSE-регистре для банков осцилляторов/модов — реальный ×2.5–3.5 прироста.
8. **Тесты:** нулевой вход → нулевой выход; NaN-детектор; DC-блокер на мастере (в демке добавлен: `y = x − x₋₁ + 0.9992·y₋₁` — иначе warp/fold давали до 1.6 % постоянки); пик ≤ 0 dBFS на всех 717 пресетах (у нас до фикса было 0.99+ на 5 из 11).

## 11. Как это ляжет на C++/JUCE

```cpp
// один движок = один класс, общий интерфейс
struct Engine { virtual void start(int note,float vel,float sr)=0;
                virtual void prepare(const Params&,float sr,int n)=0;
                virtual float render(const Params&)=0; };

// голос держит 8 слотов; слот выбирает движок по enum и не пересоздаёт его при смене
struct Voice : juce::SynthesiserVoice {
    std::array<std::unique_ptr<Engine>, 8> slots;   // создаются один раз на все 8 типов? нет:
    std::array<EngineVariant, 8>           engine;  // лучше std::variant<WT,Gran,FM,...>
    std::array<EngineParams, 8>            params;  // POD, копируется из APVTS на блок

    void renderNextBlock(AudioBuffer<float>& out, int start, int n) override {
        for (int i = 0; i < n; ++i) {
            float sumL = 0, sumR = 0;
            for (int s = 0; s < 8; ++s)
                if (mask & (1<<s)) { float v = std::visit([&](auto& e){ return e.render(params[s]); }, engine[s]);
                                     sumL += v * panL[s]; sumR += v * panR[s]; }
            svf.process(sumL, sumR);            // фильтр на голос
            float env = ampEnv.getNextSample();
            out.addSample(0, start+i, sumL*env*gain); …
        }
    }
};
```

Ключевые решения, которые дорого менять позже:
- **`std::variant` вместо наследования** для движков — без виртуальных вызовов в горячем цикле и без `unique_ptr`-прыжков по памяти (лучше для кэша).
- **`EngineParams` — POD**, заполняется один раз на блок из `AudioProcessorValueTreeState`. Движки не знают про параметры JUCE.
- **Контент отдельно от кода:** вейвтейблы и сэмплы — в бинарном бандле (свой формат: заголовок + MIP-уровни + метаданные), грузятся через `MemoryMappedFile`, а не «вшиты в бинарь».
- **Тесты на алиасинг:** прогон свипа синуса через каждый движок + FFT, проверка «нет ли пиков ниже основной частоты» — это ловит 90 % багов.

| # | Что | Зачем | Оценка |
|---|---|---|---|
| 1 | Wavetable + MIP | 50 % пресетов стоят на нём | 1–2 недели |
| 2 | FM (2 оператора) | самый дешёвый в коде, самый характерный звук | 3–4 дня |
| 3 | Sample/Organics (плеер + зоны + корпус) | «инструментальность», нужен для пиано/струнных | 1–2 недели |
| 4 | Harmonic (аддитив) | связка между WT и Resynth, дешёвый | 4–5 дней |
| 5 | Granular | «вау»-движок, но требует пулов и нормализации | 2 недели |
| 6 | Modal | самый «физический», но нужен редактор тел | 2–3 недели |
| 7 | Resynth | магия, но 70 % работы — анализ и контент | 3–4 недели |

**Правило:** не делать все 8 «наполовину». Один движок до продакшн-качества даёт больше ценности, чем восемь прототипов, — потому что именно на одном доведённом движке рождается первый пресет, который хочется сохранить.
